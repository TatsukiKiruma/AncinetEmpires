## 两个待定样本

以下 record 索引均从 0 开始。

### 6efeed8bfd52d3428de39d32：已找到新增的确定规则遗漏

原来的“超上限生命不能再次治疗”限制有 APK 对应，不能删除。`C0600q.m4295h` 明确要求非中毒且 HP 不高于有效上限；原生回放 HEAL 经 `C0580c.m4578a` → `C0586f.m4503b` → `C0595l.m4430j` 同样检查该条件，非法治疗会报错。

问题实际发生在更早的敌军占堡扣血：

1. record 7772：P5 圣骑士治疗龙 u76，生命从 100 增至 190。
2. record 7817：进入 P0 回合，该龙占据 P0 城堡。项目直接减 50，得到 140。
3. APK `C0595l.m4472a` 调用 `C0600q.m4307f`，计算的是 `clamp(HP - 50, 0, 有效上限) - HP`。本例上限为 100，因此原生应从 190 变成 100。
4. record 7822：原生目标为 100 HP，后续治疗合法；项目残留 140 HP，严格动作检查拒绝治疗。

除 JADX 方法外，还核对了原始 `classes.dex`：`Lc/a/b/a/l;->a()V` 的字节偏移 0x01da–0x01ea 读取负城堡伤害，0x01ec 调用 `q->f(unit,int)`；后者调用四参数钳制函数并减去原生命。因此这不是依赖反编译器不完整控制流推测出的结论。

判断：**这一失败点可由项目敌城堡扣血缺少上限钳制解释，不需假设 mod。** 这不能证明整份对局从未使用 mod。本轮用户授权修复的是先前四项，对两个待定项要求核查判断，因此此新增第五项仅记录证据和诊断实验，尚未修改公共规则。

诊断脚本统一补上敌军占堡超额生命钳制后，全 11936/11936 条记录通过，无非法动作、无跳过或替换；共发生 4 次钳制。它是临时反事实实验，不能计入当前公共规则的通过数，也不是 Android 原生逐状态比对。

### dfe18a69c9affc588808e13e：原生占格限制存在，前序分歧仍待定

APK `C0600q.m4329c`（815–820 行）和 `C0595l.m4428k`（982–1005 行）明确要求目标格为空或为同一单位，回放 MOVE 执行也检查，不能允许两单位重叠。

已追查到：record 4037，2 级龙攻击水中人鱼 u317，造成 90 伤害，留下 10 HP；record 4077，人鱼水中恢复至 20；直到 record 4121 没有移走或再次受击，因而挡住另一条人鱼。按项目当时得到的输入，APK 伤害公式也是 90：基础攻击 90，飞行水攻 +10 与水之子防御 +10 抵消，距离 2 无近战倍率。龙此前经验 0→60→120→180→210→240→300，对应 2 级，也符合原生阈值。

判断：**尚未找到应修改占格或该击伤害公式的证据；不能认定为 mod，继续保留为前序状态分歧待定。** 更早的命令只有动作，没有权威 HP、经验快照；上述计算一致依赖上游输入状态一致。需要 APK 原生在相关记录处的状态及实际运行脚本，才能区分更早结算漂移与运行时修改。

两项均不能通过放宽合法动作或删除占格单位来“修复”。当前训练仍应隔离这些异常对局。此前已确认的 mod 是 065、078；097 仍仅为历史疑似，不能因排除四项项目问题就将其升级为确认 mod。
