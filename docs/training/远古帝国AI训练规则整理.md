# 远古帝国 AI 训练规则整理

本文是面向规则引擎、自动对战和 AI 训练的规则手册，已合并原兵种数据和地形分析文档。若本文与本地代码存在差异，以“当前实现状态”段落说明为准；后续开发应逐步把代码对齐到“目标规则”。

## 2. 当前实现状态

本地代码已具备：

- 16 类正式地形。
- 20 个正式兵种。
- 结构化动作、合法动作生成和非法动作拦截。
- 状态、治疗、召唤、支援、修理、破坏、墓碑、光环、经验和等级。
- Gym-like `AncientEmpiresEnv`，提供 observation、legal actions、action mask 和稀疏 reward。

本地代码尚未对齐的目标规则：

- 招募动作仍是旧的 `recruit`，不是 `recruit_to_castle` / `recruit_and_deploy`。
- `GameState` 尚无 `pendingUnitId`。
- 招募后新单位当前直接视为已行动，不能立即进入行动选择。
- 招募部署目标仍偏旧逻辑，需要改成按兵种移动规则计算可达空地。

## 7. 城堡招募目标规则

城堡招募是当前最高优先级待收口机制。

通用限制：

- 只有己方城堡可以招募。
- 玩家金币必须足够。
- 目标兵种必须可购买；指挥官和骷髅等特殊单位不按普通招募处理。
- 城堡上有非指挥官单位或敌方单位时，不能招募。
- 招募成功后必须设置 `pendingUnitId`，强制新单位先完成行动。

空己方城堡：

```ts
{ type: "recruit_to_castle"; unitClass: UnitClass; castlePos: Position }
```

- 新单位生成在城堡本格。
- 新单位进入待处理状态。
- 待处理单位可移动、待机，若射程内有目标也可攻击。
- 如果选择待机，则停留在城堡本格。

己方指挥官位于己方城堡：

```ts
{ type: "recruit_and_deploy"; unitClass: UnitClass; castlePos: Position; to: Position }
```

- 新单位不能生成在城堡本格。
- `to` 必须是该兵种从城堡格出发，按自身移动力、地形消耗和阻挡规则可到达的空地。
- 如果某兵种没有任何合法部署目标，则不能生成该兵种的招募动作。
- 招募完成后，新单位进入待处理状态。
- 建议部署消耗本次移动，后续只允许攻击或待机；如果允许继续移动，必须明确剩余移动力计算规则。

`pendingUnitId`：

- `pendingUnitId` 存在时，只生成该单位的合法动作。
- 禁止结束回合。
- 禁止继续招募。
- 禁止操作其他单位。
- 待处理单位执行移动后，如果没有结束行动，继续保持 pending。
- 待处理单位执行会结束行动的动作后，清空 pending。

## 8. 移动与阻挡

- 单位移动使用曼哈顿方向。
- 普通单位不能穿过敌方单位。
- 普通单位可以穿过友军，但不能停在友军所在格。
- 任何单位不能停在已有单位的地块上。
- 飞行单位所有地形移动消耗 1。
- 飞行单位可以飞越非飞行敌方单位，但仍不能停在被占用格。
- 空军不享受地形防御加成。
- 空军无法被地面单位治疗。

示例：

- 士兵移动力 4，连续雪地移动消耗为 1，可移动 4 格。
- `雪地 -> 山脉 -> 雪地` 消耗为 `1 + 3 + 1`，需要 5 移动力。
- `雪地 -> 森林 -> 雪地` 消耗为 `1 + 2 + 1`，需要 4 移动力。

## 9. 战斗与伤害

攻击类型：

- 物理攻击使用目标物理防御。
- 魔法攻击使用目标魔法防御。

基础公式：

```text
最终伤害 =
(
  单位攻击
  + 特殊地形攻击加成
  + 其他攻击加成
  - 单位实际防御
  - 地形防御加成
  - 特殊地形防御加成
  - 状态防御加成
)
* 当前血量 / 单位最大血量
```

规则：

- 最终伤害向下取整。
- 最低伤害暂按 0。
- 战意单位伤害不受当前血量影响。
- 空军不享受地形防御加成。
- 虚弱状态防御 -5。

特殊修正：

| 来源 | 修正规则 |
| --- | --- |
| 神射手 | 对空军攻击 +10 |
| 死亡收割者 | 攻击有中毒、致盲、虚弱的目标时攻击 +20 |
| 破坏者 | 攻击城镇上的敌人时攻击 +10 |
| 近战大师 | 近战最终伤害 ×1.5 |
| 远程防御 | 被远程攻击时最终伤害 ×0.5 |
| 攻击光环 | 近战攻击 +10，远程攻击 +5 |
| 地形之子 | 匹配地形时攻击 +10、防御 +10 |

反击：

- 目标存活且攻击者在射程内时可反击。
- 反击伤害使用同一公式。
- 反击风暴可以对 2 格内攻击反击，即使单位致盲。
- 反击造成伤害给经验，反击击杀给额外击杀经验。
- 反击不触发投毒或致盲。

## 10. 状态、治疗与墓碑

状态互斥：

- 单位同一时间只拥有一种状态。
- 已有状态不会被其他状态替换。
- 净化可清除中毒、致盲、虚弱。

中毒：

- 投毒者主动攻击命中后附加。
- 对拥有投毒者能力的单位无效。
- 每次己方回合开始扣 10 血，持续 2 次。
- 第三次己方回合开始清除状态，不扣血。
- 中毒期间地形回复失效。
- 中毒单位不能被治疗师治疗。
- 中毒致死时不再结算后续回复。
- 亡灵中毒当前按回血 10 处理，仍需最终确认。

致盲：

- 致盲者主动攻击命中后附加。
- 对拥有致盲者能力的单位无效。
- 致盲后主动攻击距离变为 0。

虚弱：

- 虚弱光环待机后影响 2 格范围敌人。
- 移动力降至 1。
- 物理防御和魔法防御均 -5。
- 持续 1 回合。
- 对拥有虚弱光环能力的单位无效。

治疗与净化：

- 治疗师基础治疗量 40。
- 圣骑士升级后治疗量每级 +10。
- 同一单位每回合只能被治疗一次。
- 空军不能被地面单位治疗。
- 亡灵不能被普通治疗；治疗会造成对应治疗量伤害。
- 净化光环基础回血量 10，精灵每级 +5。
- 净化光环清除范围内中毒、致盲、虚弱。
- 净化光环对亡灵造成对应数值伤害。

墓碑：

- 墓碑按中立对象建模，不是地形。
- 普通单位踩墓碑受到 10 点伤害，墓碑消失。
- 骷髅和幽灵踩墓碑回复 10 点血量，墓碑消失。
- 亡灵死亡不产生墓碑。
- 墓碑持续 2 回合；多玩家场景下的泛化仍需确认。

| `support` | 支援者重置 2 格内已待机友军，不能支援突击部队、城堡捕获者、支援者或更高等级单位。 |
| `repair` | 修理者修复损坏的城镇并结束行动。 |
| `destroy_town` | 破坏者摧毁城镇，城堡不可摧毁。 |
| `post_attack_move` | 突击部队攻击后使用攻击前剩余移动力二次移动。 |
| `wait` | 结束单位行动，并触发相关光环。 |

## 13. 回合开始结算建议

推荐顺序：

1. 当前玩家单位重置行动状态。
2. 中毒结算。
3. 中毒致死单位直接死亡，跳过后续效果。
4. 神庙净化。
5. 地形回复。
6. 地形之子回复。
7. 自我修复。
8. 金币收入。

如果实现中收入先于单位状态结算，也应保持确定性，并在测试中固定该顺序。

## 14. 训练环境接口

规则引擎至少需要支持：

```text
getState()
getLegalActions(playerId)
step(action)
isTerminal()
getWinner()
clone()
reset(config)
```

训练环境至少需要支持：

```text
reset(seed?)
step(actionIndex)
stepAction(action)
getObservation(playerId?)
getActionMask()
clone()
encodeAction(action)
decodeAction(code)
```

observation 必须是纯 JSON 对象，包含：

- 当前玩家和回合。
- 地图尺寸。
- 玩家金币、存活状态、指挥官死亡次数。
- 地形、建筑归属。
- 单位 id、阵营、兵种、坐标、血量、等级、经验、行动状态和状态。
- 墓碑列表。
- 后续应增加 `pendingUnitId`。

AI 编码建议：

- 16 类地形 one-hot。
- 防御力加成、移动消耗、每回合回复、每回合收入。
- 建筑归属、是否可占领、是否可摧毁、是否可修理、是否可招募。
- 单位类型、阵营、血量、状态、是否已行动。

## 15. 验收标准

- 随机 AI 可在小地图上连续自动对局 100 局不崩溃。
- 所有 `getLegalActions()` 生成的动作都能被 `step()` 执行。
- 所有非法动作都能被拒绝，且完整状态不变。
- 同一初始状态和动作序列得到完全一致结果。
- `clone()` 副本修改不影响原状态。
- 训练环境不依赖 UI，也不使用测试绕过。
- 招募新规则和 pending 行为有完整测试覆盖。
