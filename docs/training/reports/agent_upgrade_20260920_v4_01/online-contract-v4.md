# 在线运行时 1 秒请求边界与看门狗契约 (Online Contract v4)

**规范版本：** v4.0  
**审查基点：** `85a87a0edb64de18a8b8eced9226ffb1cd1b48e9`  
**约束目标：** 每个底层 Action 调用方单调时钟端到端上限 1000ms；真实时延严禁裁剪。

---

## 1. 计时与控制边界

1. **时钟权威源：** 调用方单调时钟 `performance.now()` 从决策请求发起时刻 $t_0$ 起算，至结果返回并完成合法性校验时刻 $t_{\text{end}}$ 为止：
   $$\text{e2eMs} = t_{\text{end}} - t_0$$
   严禁将内部搜索循环的子阶段时间当作完整端到端时延上报。

2. **杜绝耗时裁剪：**
   彻底移除 `Math.min(deadlineMs, lastNow - startedAt)` 逻辑。实测耗时 1050ms 即记录 1050ms，1200ms 即记录 1200ms。任何突破 1000ms 的请求必须在遥测中标记 `deadlineMiss: true`。

3. **分阶段内部预算水位（基于 1000ms 预算配置）：**
   - **850ms：** 停止波束展开与新分支搜索，锁定已有最佳 candidate。
   - **950ms：** 完成格式化与动作解码，进入返回准备。
   - **1000ms：** 硬看门狗截止目标；超时立即触发熔断，交付预校验的合法动作。

---

## 2. 取消机制与安全回退

1. **外部取消 (AbortSignal)：**
   当用户在前端切换地图、点击重开、手动单步、步进下一回合或终止自动对局时，通过 `AbortSignal` 立即作废当前在途计算。

2. **状态版本隔离 (State Versioning)：**
   每个决策请求携带 `stateVersion`。若计算返回时引擎状态已改变（例如回合已推进），旧动作一律作废丢弃，严禁套用到新状态。

3. **预校验合法回退 (Cheap Fallback)：**
   在启动昂贵搜索前准备确定性合法动作（如原生启发式 `HeuristicAI` 或经过规则引擎校验的首个合法动作）。超时或异常时立即交付，保证游戏永不崩溃、永不产生非法动作。

4. **真实非硬实时环境声明：**
   浏览器主线程受操作系统进程调度与 GC 抖动影响，并非严格硬实时系统。看门狗机制提供可降级的截止保护，但真实超限数据必须完整记录并纳入门禁裁决。
