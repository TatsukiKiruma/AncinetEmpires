## 2. 可直接从本次数据下的结论

1. **工程层：修复是有效的、可验证的。** 120 场 0 引擎错误、0 加载错误、0 NOT_RUN、0 次超过 1000ms；两座位、5 图全部跑通；逐场记录 commit / dirty patch hash / 模型 SHA / 种子流 / 预算。
2. **固定节点预算重放已真正可复核。** 移除搜索墙钟依赖后，两次独立运行在全部博弈与搜索投入字段上 **4/4 完全一致**（仅墙钟延迟不同）。
3. **`SPATIAL_V2` 与 `SPATIAL_DAGGER` 在 20 场内未战胜 Heuristic。** 但见 §3 的关键限定。
4. **S00 与 S10 的差距远小于上一批次所述。** `reeval_01` 报 6.7% vs 46.2%（差约 40 个百分点）；本次为 21.4% vs 41.7%（差约 20 个百分点），且 S10 在 Duel 上 2 胜 2 负。**"S10 远差于 S00" 不能作为已确立的性质。**
5. **"负向先验偏差" 在数据中找不到支持，反而有反证。** 评审用配对诊断（155 个真实决策点、同状态同预算 S00 vs S10）显示：启发式 top 动作被先验排挤的次数为 **0/155**；先验把启发式最优动作排在 **0.441 百分位**（接近随机）；S10 在 35 次中更差、26 次中更好。先验的问题是**弱（近噪声，logit 极差约 0.134）**，不是**有害**。
6. **重招募率不是棋力指标，不应进入胜负结论。** 本批次 6 个策略中，最弱的 `SPATIAL_V2`/`SPATIAL_DAGGER` 反而拿到最高窗口完成率（100% / 87.5%），而 NET_A 最低（8.3%）。该指标只反映"指挥官阵亡后是否买回来"的机制，与其是否为好棋无关。
7. **搜索的真正瓶颈是候选规模，不是先验排序。** 搜索策略每个决策平均只评估 **2.94–3.01 个候选**、约 12.8–13.1 个节点（上限 20），且 20/20 场都突破了 200ms 软预算。也就是说：先验排序影响的是一个**只有约 3 个候选**的极小集合。

## 4. 下一步（按任务书 S8-4 决策表）

任务书 S8-4 的表格要求按现象选择后续；本次现象对应两行：

- 「S10 弱于同预算 S00」→ **先检查候选保留和展开顺序，再训练先验，不先加深网络**（addendum 第 118 行）。本次证据把这一点进一步收窄为：**先修候选规模与墙钟约束**，而不是先修先验排序。
- 「正确调用后仍很差，训练曲线未收敛」→ 保留 32ch/2 块，用真实 10k→30k 有效状态与固定分区做学习曲线（第 116 行）。但**前提是先用合格 checkpoint 重做 S10/S00 对照**，否则会把冒烟模型的表现误记为架构结论。

### 建议顺序

1. **（P0，最便宜、信息量最大）换 checkpoint 重跑 S00/S10 ± 先验消融。**
   使用已有的 6.5k–7.8k 语料 checkpoint（`v8_closure_02` 或 `v8_final_01`），在**固定节点预算**下比较：Heuristic / S00 / S10(带先验) / S10(先验置零)。这能一次性回答"先验是弱还是有害"。
2. **（P0）候选规模与墙钟消融。** 当前搜索每决策只评约 3 个候选却已突破 200ms。需要在**固定节点预算**下扫描 `maxTotal` / `topSpatialK` / `tacticalQuota`，并记录每个候选是否到达对手、对手动作数、是否覆盖"移动后攻击"。这是任务书 6.1/6.3 明确要求、至今仍缺的覆盖遥测。
3. **（P1）冻结并按地图/座位分层验证集。** 现 val split 取生成序前 15% 根家族，`v8_final_01` 的 13 个 val root 中 Duel 与 Liberty Port 各 0 个。不分层的 val accuracy 不能作为学习曲线依据。
4. **（P1）在合格 checkpoint 上重做 5×2×2 对照，再决定是否扩量。** 若 S00/S10 在合格 checkpoint 上仍然平庸，才进入 10k→30k 数据路线。
5. **（P2，仅在获得明确算力预算后）** 30k 数据 + 2 块 vs 4 块深度对照。当前 30k 在 `stage1_training_design.md` 中为 `BLOCKED/NOT_RUN`，且 curriculum 距自身目标 832/3000、ENDGAME 层 0 样本、`valueTarget` 非空 0/7832。
