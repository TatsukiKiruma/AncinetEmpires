## 2. 核心反例暴露与修复验证清单

### 2.1 数据索引与结果视角 (N01 / F02, F07)
- **反例复现：** `tools/skirmish_dataset_vnext_n01.test.ts` 暴露重标记样本中以候选局部序号覆盖 `fixedActionIndex` 导致的数据污染，以及 `sampleIdSeed` 字段被篡改时旧校验静默通过的问题。
- **修复措施：** `tools/skirmish_dataset_vnext.ts` 强化跨字段哈希与强类型校验，明确区分 `perspectivePlayerId` 与 `perspectiveAllianceId`，非法样本隔离至 `quarantine.jsonl`。
- **结果：** 28 项数据集测试 100% 通过。

### 2.2 动作语义与空间表示版本 (N02 / F01)
- **反例复现：** `tools/skirmish_network_features_n02.test.ts` 构造了 5 组真实规则可达的完全相同 32 维特征的动作对（两座城堡同时招募、同城堡不同部署格、不同城镇破坏、相同兵种不同坐标敌军攻击、不同起点同终点移动）。
- **修复措施：** 实现 45 维 `encodeGameActionV2`，显式编码几何坐标 presence 掩码与归一化位置，接入 `getActionSemantics`。
- **结果：** 碰撞率降至 0.0%，不使用哈希截断或随机降维。

### 2.3 搜索集合配额与真实对手阶段曝光 (N03 / F03, F04, N03-A)
- **反例复现：** `tools/skirmish_search_teacher_n03.test.ts` 暴露模型高打分动作在旧 beam 排序中被启发式完全截断抹除（F03），以及 pending 招募无法交出击时谎报已进入对手阶段（F04）。
- **修复措施：** `tools/skirmish_search_teacher.ts` 实现 `selectBeamCandidates`（保护 capture/tactical/model/explore 专属配额）；`handToOpponent` 在无 `end_turn` 时显式返回 `stop: 'incomplete'` 并拒绝进入对手回应推演；引入 850ms 停止新增展开机制。
- **结果：** 15 项搜索教师测试全部通过，在线时延样本 100% 满足 $\le 1000\text{ ms}$。

### 2.4 数值梯度、严格模型契约与动态层数 (N04 / F06, N04-A)
- **反例复现：** `tools/skirmish_dual_head_net_n04.test.ts` 暴露旧模型加载器遇到缺失或非有限权重时静默补全为随机初始化的致命隐患，以及标准化折叠未校验非正数 $\sigma$ 和重复折叠问题。
- **修复措施：** `tools/skirmish_dual_head_net.ts` 引入 `trunkLayers` 动态数组实现 NET_A (`[256, 128]`) 与 NET_B (`[256, 256, 128]`)；实现单样本中心有限差分校验 `checkGradients`；实现零分配推理路径 `predictDecision`；加载器严格强制检验所有张量长度与有限性。
- **结果：** 有限差分梯度最大相对误差 $< 4.2 \times 10^{-6}$（远低于 $10^{-3}$ 门限）；全量回归通过。
