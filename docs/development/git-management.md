# Git 文件管理与分批提交

## 文件边界

- Git 保存公共源码、训练源码、配置模板、测试、轻量说明、精选证据和应用实际使用的发布资产。
- `public/models/` 与 `src/game/ai/models/` 是应用发布资产，不按训练缓存删除。权重、元数据、加载器和登记表必须配套。
- 原始回放、训练数据、张量、优化器状态、实验 checkpoint、手机部署包、解包 APK、Python 环境与缓存留在独立归档。禁止提交账号配置和密钥。
- 历史源码副本、带时间戳的生成脚本、完整运行现场不重复上传；需要复现时根据实验记录到本地归档查找。
- 原始工作区没有被清理或覆盖。本分支删除的是新版本中的 Git 跟踪项；旧提交仍保留历史对象，因此不是历史瘦身或凭据清除。
- 历史报告按原文保留。报告中声称存在的资产、运行进度和授权不是当前状态；本次不保证退休实验能够独立复现。

## 提交流程

1. 使用明确路径或 `git add -p` 暂存，禁止直接批量加入研究目录。先检查 `git diff --cached --stat` 与具体差异。
2. 执行 `python tools/check_git_files.py` 检查暂存内容。普通 Git 单文件管理上限为 10 MiB；这只是项目管理规则，不是服务端上限。脚本仅做初筛，不能替代人工敏感信息检查。
3. 公共代码运行 `npm run lint`、`npm test`、`npm run build`；训练代码运行独立检查。APK 证据测试需要本机解包目录，缺失时不能记为通过。
4. 提交说明使用中文。按规则、AI、界面、研究迁移、工具文档和资产管理分别提交；关联批次需要按顺序一起使用。
5. 首次发布推送专用整理分支，核验后再合并。不要从旧本地 `main` 合并巨型训练产物提交，也不要使用 `push --all` 或强制推送。
