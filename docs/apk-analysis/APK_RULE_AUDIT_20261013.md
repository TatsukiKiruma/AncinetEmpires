# APK 4.2.5.1 规则与训练环境审计

审计日期：2026 年 10 月 13 日。对象为当前工作区和用户指定的 `APK/aer-release-4.2.5.1.apk`。

后续状态：本页保留修复前的审计事实和反例输出；随后完成的修复见[规则修复和交付范围](../rules/apk-rule-fixes-20261013.md)，不要把下文“当前项目”误当作修复后的实时状态。

**当前项目没有完美复刻 APK；已经存在会改变正常 SD 遭遇战策略的确定性差异。建议修复下列高优先级问题、重建独立规则验收后，再进行昂贵的正式训练。** 现有模型和数据应保留，但其评测成绩不能直接解释为 APK 实战能力。

本次只新增审计文档、探针和结果，未修改游戏规则、地图资产或训练实现，也未回滚工作区既有改动。

## 影响训练的已确认差异

### 地形表解析错位

这是本次最严重的发现。`tools/apk_terrain_report.ts:164` 将地形记录按固定 40 字节和固定偏移读取，但 APK 的记录包含可变长度数组。

APK `p036c/p037a/p038a/C0573c.java:122,144` 先读取数组及对象的空标记；`p036c/p037a/p039b/p040a/p044v/C0619b.java:46` 依次读取 land、kind、数值字段、`int[] f1377j` 和最后的图形类别。资源装载 `p036c/p037a/p039b/p049b/C0656i.java:353` 连续读取地形和单位两个对象数组。

独立解析结果：

- t0 位于解密载荷 `[9,49)`，40 字节。
- t1 位于 `[49,93)`，44 字节，因为内部数组为 `[2]`。
- t2 从 93 开始，旧解析器却从 89 开始。
- 84 项读取完在偏移 3373，恰好读到下一段 magic `365703`、非空标记和单位数 `21`。此边界验证不依赖项目固定跨度表。
- 项目地形表 **80/84 项 kind 与 APK 字段不同**；t2 以后旧 kind 实际落在前一条记录的图形类别上。t0/t1 的移动成本还从 3 错读成了 16777215。

实际调用 `getMoveCostForUnit/getAttackBonus` 的反例：

| 局面 | 当前项目 | APK 数据和规则 |
| --- | --- | --- |
| 士兵进入 t0 水域 | 消耗 16777215，正常移动不可达 | 消耗 3 |
| 石人在 t2 水域 | 移动消耗 1，地形攻击加成 10 | 消耗 3，没有山地加成 |
| 狼射手在 t17 山地 | 移动消耗 1，地形攻击加成 10 | 消耗 3，没有森林加成 |

影响路径包括 `abilities.ts:45-57,132-138,168,189` 和 `engine.ts:361-364` 的地形之子回血；APK 移动方法为 Q.m4357a，回血方法为 Q.m4342b。错误标签会追加到原有标签上，例如 t17 可同时被判为山和森林，并非简单互换。

这不是冷门战役边界：官方 20 图的使用表中，t0/t1 合计 683 格、涉及 18 图；t2 有 34 格、涉及 5 图；t17 有 313 格、涉及 19 图。它会改变走位、地形战斗收益、回血和单位价值。

`apk:terrain-report --check` 用同一个错误解析器与同源归档比较，因此仍然通过。不能把该通过当作 APK 语义正确的证据。

### 大地之子在水面的移动成本错误

即使只修正地形 kind，这个问题仍存在。APK Q.m4357a（306 行起）规定大地之子在陆地消耗 1，在非陆地消耗基础值加 1；普通水面为 `3+1=4`。

官方地图导入 `src/game/apk_map.ts:453-461` 保留 `apkTerrainId`，未写入 `apkTerrainIsLand`。`abilities.ts:142-150` 因直接字段缺失走旧水面兜底，返回 2。探针确认 t2 上狂战士移动成本为 2，应为 4；同能力的其他单位也受影响。模型会高估此类单位渡水速度。

### 致盲后仍允许邻接治疗和召唤

APK Q.m4258t/m4257u（1416 行起）在致盲时把最大和最小射程都置为 0。Q.m4300g 召唤检查经 Q.m4313e 使用该射程；女巫自己占据距离 0 的格子，因此不能召唤。非亡灵治疗目标由 Q.m4276k（1284 行起）检查有效射程或自身。

项目 `rules.ts:282` 把治疗距离固定为不大于 1，`:388` 把召唤距离固定为不大于 2。实测致盲女巫仍有邻格召唤动作，致盲圣骑士仍有治疗邻格非亡灵指挥官的动作。训练动作 mask 将 APK 不允许的行动当作合法策略，削弱致盲在训练环境中的效果。

### 召唤骷髅的累计经验初值错误

`engine.ts:673-674` 继承女巫等级，但把骷髅经验设为 0。APK Q.m4369a 调用 Q.m4333c，后者在 755 行用 `C0613f.m4201a(level)` 初始化累计经验。等级阈值为 100、300、600。

实际执行召唤后，1 级骷髅经验为 0；再获得 200 经验仍为 1 级，而 APK 基线从 100 开始，应升到 2 级。2 级召唤物也会出现同类延迟。模型会低估高等级召唤物的成长收益。

### 允许占领盟友建筑

APK Q.m4321d（897 行起）通过 Q.m4325d 拒绝占领同盟所有者的建筑。`rules.ts:417` 只判断 `ownerId !== playerId`，没有排除盟友；引擎 capture 分支随后实际转移所有权。

探针使用玩家 0、1 同盟并保留敌方玩家 2，确认玩家 0 的士兵站在玩家 1 村庄时会获得 capture 动作。该差异影响联盟、多方训练；普通双人敌对局面不触发。

### 淘汰后没有完整清理败者资产

本次解密的 SD controller 在玩家无兵无城后调用 `Stage.SyncDestroyTeam(team)`。APK `C0598o.java:651-660` 调用 `p042t/C0607b.java:275-286`，把该队领地改为中立 owner 4094，并移除该队单位。

项目自然淘汰 `engine.ts:975` 仅设置 `isAlive=false`；公共脚本 API `apk_stage.ts:225-231` 同样未清理领地和单位。相比之下，surrender 分支已有清理。

官方四人 Crossroads 地图副本的探针：让玩家 0 无兵无城但保留一座村庄，推进后玩家 0 已淘汰、整局仍继续，其村庄却仍有 owner 0。直接对正常初态调用 `syncDestroyTeam` 后，该队仍保留 2 块领地和 1 个单位。前者影响多人 SD 的占领、阵营及建筑归属；后者还影响使用该 API 的脚本场景。

## 回放通过不能证明训练规则正确

`src/game/apk_replay.ts:830` 的 forced 模式绕过合法动作验证；`:851-856` 同时允许缺失来源单位、非法招募及部分无效事件转为空操作。`:919` 的成功条件只是 `firstError===null`，没有 APK 每步 HP、金币、经验、状态和胜负的逐项真值比较。

本次构造一条来源格没有单位的 ATTACK：strict 返回失败；forced 返回 `success=true, executedRecordCount=1, expandedActionCount=0`。此外，`apk_replay.test.ts:56` 已把“越界攻击在 strict 和 forced 中都展开为零动作并通过”写为现行预期。因此 strict 也不是对原始动作无损、逐状态的等价证明。

另一个关键差异是数据入口：`tools/apk_game_get_validate.ts:921-923` 从回放嵌入数据注入 `apkTerrainKind/apkTerrainIsLand/apkMoveCost`；官方训练地图入口没有这三个覆盖。回放局面可能绕开地形表错误，不能据此给官方地图训练路径背书。

历史 065/078 的 mod 归因、097 的未决运行态差异仍应保留。本次不据此修改全局规则，也不把新发现反向归因到这三个样本。

## 训练接口和复刻范围

现行 V19 训练链复用公共 `GameEngine`，因此公共规则差异会传递给它。正常 `sd-normal` 开局使用 SD、300 金币、30 单位上限和 3 等级上限；首回合收益、reset 和 clone 路径未发现重复结算。训练主动过滤 surrender 是策略空间选择，不是 APK 引擎错误。

`env.ts:710-738` 的 maxPlies 截断可按金币、军力给出代理 ±1，不能当作 APK 自然胜负。但 V19 `ai_training/v19/env/subject_episode.ts:499,513-566` 直接执行 engine，只按规则 winner 标记终局，已避开这条代理奖励路径；不能声称当前 V19 标签因此受到污染。

V19 可选 `maxPlies` 有另一个接口问题：`:383` 循环只限制 maxSteps，`:511-512` 用原子动作数判断截断，`:560` 又用回合数分类。官方 Duel、seed=424242、maxSteps=6、maxPlies=1、predictor=null 的探针执行了 6 步后才归类 TRUNCATED_PLY_LIMIT。默认 maxPlies 为 null，此问题不影响默认参数，且属于训练截断合同而非 APK 战斗规则。

完整 APK 范围还存在以下限制：

- 战役单人难度减伤：APK Q:657 对指定玩家类型应用 0%、25%、50% 设置；项目无相应倍率。默认 SD 配置为 0，不能据此判定默认伤害公式错误。
- 达到等级上限后，APK `C0595l.java:255` 阻止继续增加正经验；项目 `abilities.ts:303-307` 仍累积经验但不升级。默认满级战力不变，经验观测不同。
- 战役脚本调度、剧情目标及任意远端 mod 不属于当前 SD 正常训练链的完整复刻承诺。移动 override 的额外 id 兜底及非正值处理与 APK 存在静态差异，尚未给出实际战役触发样本，列为后续核查。

## 修复和重新验收顺序

1. 按 APK 对象协议重建地形解析，校验数组边界与全部字段；通过生成工具更新资产，不手改生成地图文件。增加直接来自 APK 字节的独立预期，避免解析器与归档相互证明。
2. 统一官方地图、远端回放和自定义局面的权威地形语义来源，修正大地之子水面移动。对相同状态比较各入口的合法动作、伤害、回血和移动成本。
3. 修复致盲治疗/召唤、召唤经验、同盟占领及淘汰清理，并把本文反例加入真正的规则回归。
4. 给回放输出显式的跳过、替换、歧义计数；将“可播放前缀”“合法动作一致”“每步状态一致”作为不同指标。保存 APK 对照局面的状态快照，比较 HP、经验、金币、行动标志、墓碑、状态、阵营与 winner。
5. 以修复后的规则生成版本标识，重新评估已有模型和数据来源。保留历史资产；区分 APK 原始回放与错误模拟器生成的自博弈状态，不直接混用。

在上述验收前，不能保证训练不会学到 APK 中无效的策略。增加回放数量本身无法修复数据入口差异和宽松验证器的问题。
