# Ancient Empires Reloaded APK 4.2.5.1 规则还原审计

**截至 2026 年 11 月 7 日，当前项目对 APK 默认遭遇战（SD）的常规规则还原度较高，但不能视为完全等价。** 兵种、地形和已有遭遇战检查支持这一判断。本次独立探针复现了三处会改变合法动作的偏差，其中一处还会跳过单位的墓碑结算。另有一项明确记录的有意数值差异：项目把水晶的基础移动力从 4 设为 0。

## 三处可复现的动作差异

| 局面 | APK 原生规则 | 当前项目实测 |
| --- | --- | --- |
| **指挥官占堡，新兵无格可走** | 先计算新兵的合法落点；没有落点就拒绝招募，拒绝发生在扣费前。 | 3×3 路面图，指挥官在中心城堡，四个正交邻格都被敌兵占据。项目仍接受招募士兵，金币 **600 → 450**；新兵与指挥官堆叠，没有可移出的格子。移去东侧敌兵后，新兵能正常走到该格。 |
| **投石机摧毁脚下村庄** | 毁村走攻击目标判定，要求目标在 **3–5 格**射程内且无人占据。脚下村庄既是 0 距离，也有投石机占据。 | 项目额外生成原地毁村动作，执行后己方村庄变成中立废墟。对照组中，距离 3 的空村庄可以摧毁，距离 4 的占用村庄不能用毁村动作直接摧毁。 |
| **突击再移动尚未收尾** | 还剩移动力的突击单位进入阶段 3。该阶段可处理当前单位的移动；选择其他单位或结束回合的入口只接受阶段 0、1。 | 龙走到墓碑上并攻击后，项目同时允许龙原地收尾、另一名己方士兵待机和直接结束回合。龙原地收尾时 **100 → 90 HP**、墓碑被消耗；直接结束回合时龙仍是 **100 HP**、墓碑仍在，控制权已转交敌方。 |

三个局面的项目端证据同时核对了合法动作生成器、`GameEngine.hasLegalAction` 和 `AncientEmpiresEnv` 固定动作掩码，并执行了相应动作。它们不是只在界面上出现的选项。完整初态、动作编码、掩码索引、对照组和执行后状态见 [evidence.json](evidence.json) 的 `differences`。

APK 原生依据：堵死招募见 [`m4344b` 的落点检查](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0600q.java#L698)和 [`m4445c` 的校验与扣费顺序](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0595l.java#L646)；毁村见 [`m4362a` 的射程与占位检查](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0600q.java#L578)；突击见 [`m4452b` 的行动收尾分支](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0595l.java#L528)、[`m4572b` 进入阶段 3](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0580c.java#L350)、[`m4460a` 的选择阶段限制](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0595l.java#L437)及 [`m4441e` 的结束回合限制](../../../APK/_analysis/jadx_output/java/p036c/p037a/p039b/p040a/C0595l.java#L755)。这些是已有原生代码的静态证据；本次没有启动 Android 对局。原始 `classes.dex` 中四条相关拒绝提示的方法签名及代码偏移另见 `dexReferences`。

## 已核对的一致范围

| 检查 | 结果 | 结论边界 |
| --- | --- | --- |
| 兵种数据 | **21/21 条记录**；未发现未解释的项目配置差异 | 三条费用字段差异来自表达方式：指挥官费用走重招规则，骷髅与水晶不走普通招募。真正的基础数值差异是水晶移动力 **APK 4、项目 0**。 |
| 地形数据 | **84/84 条记录**；项目的 APK 地形归档与原始数据无差异 | 验证了原始字段及归档一致性；不代表所有地图贴图映射或脚本覆盖都逐格实测过。 |
| 遭遇战规则 | **30/30 项通过** | 覆盖开局设置、SD/SO 招募名单与费用、指挥官储备、地形恢复和防御、城堡伤害、投降、淘汰等已列检查。三个新探针单独报告；30 项通过并不能覆盖这些动作边界。 |

例如，默认的村庄收入 **50**、城堡收入 **100**、指挥官收入 **50＋25×等级**和指挥官重招价格曲线已有原生规则依据。常规战斗的血量缩放、近战与远程伤害倍率、攻击附加状态与反击顺序也有原生代码对照，见 [既有规则审计](../APK_RULE_AUDIT_20261013.md#当前检查结果)及 [APK 伤害与反击核对](../OPENCODE_APK_Verified_Mechanics.md)。范围限于已核对的默认规则；战役、自定义脚本、其他发行版本和所有对局的逐步状态一致性不在本次结论内。

## 证据与复现

- [证据快照](evidence.json)：原始 APK、包内 `assets/data.bin` 与 `classes.dex` 的 SHA-256；与本地解包件的比对；项目源码哈希；检查结果；三个探针输入、动作和后态。APK 整包 SHA-256 为 `51b00185f300dd8899284aa91986aee9a1cc73fa012262a0d9eebc97fad1aa7b`。
- [复现脚本](probe.mjs)：复用项目的权威引擎和 APK 检查工具。它只读取本地材料，在内存中运行探针，向标准输出写 JSON；断言不成立时以非零状态退出。

在仓库根目录执行，需具备项目 Node.js 依赖、`tar`、本地 APK，以及仓库规定位置的既有解包件和原生分析文本：

```powershell
node --openssl-legacy-provider --import tsx docs/apk-analysis/parity-20261107/probe.mjs
```

证据快照记录的是本次工作区。若源码后来更新，应以当次复跑结果和源码哈希为准。动作回放可用于检验样本能否执行；即使严格回放通过，也不能替代原生和项目逐步状态快照的比对。
