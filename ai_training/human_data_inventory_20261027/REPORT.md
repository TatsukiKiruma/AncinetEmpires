核对日期：2026-10-27，北京时间。结论来自本次现存文件检查与明确标注的历史验收；没有运行 strict、forced、APK 原生重放、训练、采集或手机操作。只在本目录写入盘点产物，没有改公共规则、旧数据、冻结分区或手机训练源码，也没有干预另一个对话的 414 局任务。

**确实还有大量多人数据。当前现存多人原始响应为 328 份唯一字节内容，另有 202 份战役回放。它们不能称为 530 个统计独立完整真人对局。现存历史策略来源标签共 558,710 条，其中明确由真人控制的为 117,510 条；这里包含开发分区和前缀，尚不是当前 2M 训练器可直接读取的训练集。**

但是实际发现：

**当前 2M 训练器可直接消费的人类训练样本，本次确认数为 0。** 原因具体如下：它现在读取 native `config.bin / result.json / actions.jsonl.gz / states.bin.gz`，没有多人来源包或战役 reader；多人保存包主要为初态＋动作＋摘要／候选索引，没有完整逐原子前态；旧已重建快照池又已清理。必须补来源适配、状态材料、候选映射、当前编码及分区过滤，不能把一个历史 `candidateIndex` 直接交给当前网络。

这不撤销已有历史验收，也不要求重新做一次完整重放。本次禁止推进状态，因此任何需要从初态顺序执行、取原生决策快照或重新生成中间态的转换都仅列为后续工作。若继续维持“完全不进行任何动作执行／动态重建”，现有文件不足以产出完整战役监督集；只能复用已有足够状态的个别材料，不能凭空补状态。

## 4. 202 份战役还缺什么

当前四种原件（response、w 对象、wt、act）202×4 全部存在且 SHA 匹配；202 个不同动作字节摘要、202 个不同规范宏流，原始动作共 40,943。历史 202 份 APK 原生胜利／回合／评分核验均通过，189 有 seed、13 缺 seed；本次仅核对回执，未再次播放。回放实际覆盖 21 关，无回放的是 TU-1、TU-2、AEI-1、AEII-1。榜单还有 971 条无回放记录，只能作统计参考。

已有 25 关地图、脚本及初始玩家／机器人队伍配置；没有逐决策完整状态快照、合法候选列表和逐动作控制者见证。初始队伍配置不足以识别剧情控制、阵营切换及强制动作。历史验证脚本只保留最终运行态摘要，没有保存最终运行态本体，更没有逐步真值。

| 转换缺口 | 可执行实现要求 | 当前处理 |
|---|---|---|
| 决策边界与状态 | 为每个真实玩家决策保存 state、规则／资源 SHA、RNG、当前玩家、联盟、单位状态、经济、关卡目标、事件阶段和脚本变量 | 尚缺，动态工作不执行 |
| 控制者及事件来源 | 标记 human / AI / script / administrative / unknown；脚本强制事件不当 policy 标签，unknown 关闭 policy | 初始队伍配置只作辅助 |
| 复合动作 | 保存 macroId/subAction，区分移动、攻击、占领、招募、后续移动／收尾，使用各原子的实际前态；不把整个宏贴在同一个局面 | 40,943 不是原子或真人标签数 |
| 候选映射 | 在真实决策前态绑定完整动作码、合法候选、有序候选 SHA、source index→编码 index；历史候选索引不直接复用 | 当前没有战役候选 |
| 脚本语义与观察 | 关卡目标、特殊保护／撤离／占领条件、脚本开关会影响动作；先判定当前观察是否足够，隐藏任务信息缺失时隔离 | 当前双流编码没有通用目标／脚本变量编码，可能产生状态混淆 |
| 地图与规则 | AEII-5、AEII-7、AEIII-1 有已记录 AEM 单位字段 -256 导入问题；保留完整初始化，不能用 terrain-only 冒充完整地图 | 采用真实原生快照投影可避免先补完全部地图导入，但投影仍需独立适配 |
| 分组与泄漏 | 同作者、同关卡路线／前缀、同初态近重复聚类；关卡内和留出关卡的评估分开 | 不按动作随机切分 |
| outcome | 全部是胜利样本；缺原始 seed 的 13 条兼容路径结果重复一致不证明原始状态 | 不训练通用胜率 value 或 return |

必须保持原生事件顺序：现有验证器是**先提交整段动作集合，再按原生队列排空**。不能改为“执行一条、排空脚本、再执行下一条”，原注释明确这种方式会在援军演出间隙触发额外 AI。后续若获准补转换，应在同一完整播放队列内部挂只读观测点，以 `(队列序号、macro、subAction、事件序号、决策边界)` 记录前态；脚本继续按原队列执行，不能人为提前、延后或再请求敌方决策。这是待实现路线，本次没有运行。

静态证据显示 107 份涉及援军相关脚本，29 份涉及脚本战斗／HP，48 份涉及移除，19 份涉及强制移动，9 份涉及地形变化，25 份涉及阵营变化，27 份涉及特殊单位状态，64 份涉及阶段标志。各项重叠；“脚本有调用”不等于每局触发该分支。无论原版还是当前困难版安装身份，都不能证明回放当年的敌方来自当前困难 AI。

转换优先级保持现有候选分类：

1. **P0：65 份 seeded_elite**，先取其中低导入复杂度的 22 份验证转换接口覆盖，再扩到 65。低复杂度关卡为 TU-3、AEI-3/6/7、AEII-2/4/6；全部低复杂度候选共 77 份，不能把 77 都称 elite。
2. **P1：32 份 seeded_near_plus2**，补充接近最短回合的不同路线；同关不同 seed 不构成受控偏好对。
3. **P2：92 份 seeded_coverage**，补恢复和不同局面，按轨迹／宏归一权重。所有较慢 96 份（含 4 份缺 seed）占原始动作 68.76%，逐动作等权会让长局支配。
4. **P3：13 份 legacy_seed_missing**，保留来源但默认 policy/value 均关闭；除非以后已有足够实际状态证据，不从“终局相同”推导“每个决策前态相同”。

25 关中 12 关存在分数与回合速度排序不一致，因此 elite 只能表示“同关已知最少回合”，不能视为最优策略或为每一步动作提高确定性正确标签。

## 5. 后续准入和隔离规则

多人旧来源最有价值：原始包、controller、macro/subAction 和保存摘要链都完整；3 个前缀也有最终过滤收据。优先使用这些证据，避免重复完整重放验收。但 reader 转换中若需要推进状态，仍是本次范围外的动态操作，不能借“只是读取”自动执行。

23 个新增字节响应中，18 个非纯投降 SD 候选有历史 strict 回执，共 12,667 条原始宏记录；没有逐决策真人标签数量，不能用宏数或 expandedActionCount 当真人样本数。3 个新 SD 分歧只保存原件和首次分歧，不能凭 strict 报告边界直接给未封存前缀准入；SR 及旧 OL/SR 保持隔离。旧 2 个信息损失来源保持隔离。

准入来源必须记录 response SHA、跨域父局键／未知、split、模式、地图、控制者、状态与动作码、候选 SHA、规则与编码 SHA、宏原子数、终局可信度及历史验收路径。policy 只接受确证 human 的决策；回放中 AI 席位另列普通 AI 来源，默认不混入“人类增强”池。它们未必是困难 AI，不应冲淡当前困难 AI 底座。未知控制者、脚本动作、投降、尾段和无法映射的候选全部屏蔽。

所有人类多人和战役的 value / return 默认保持关闭。多人 CLOSED、项目最终 winner、整条 strict 通过均不证明 APK 真实自然胜负；前缀没有终局。战役脚本胜利与遭遇战消灭目标不同，且只有正样本。以后如增加任务相关剩余回合或目标进度，应使用单独目标定义，不把榜单分数直接归一成通用胜率。

保持当前困难 AI 2414 train／268 dev 的冻结选择不变，也保持旧多人 237／59 分区不变。已消费开发、永久排重、分歧尾段优先于训练来源标签。910 个保存摘要交集需在派生训练清单中排除；跨主机相同响应、同 API 父局、相同／前缀轨迹不能跨 train/dev。战役应先做路线／作者连通分组，再分配用途；地图共享与作者共享要明示。

12 份缺失排重索引不能由旧计数恢复。可优先查找同 SHA 备份；若没有，保守复用已有最终逐行准入清单，新增数据先隔离。若以后允许从保留评测记录**静态提取已保存状态**重建索引，必须证明覆盖并封存新索引；未落盘搜索节点不可编造。评测“换一个新 seed”也不自动代表地图、作者和轨迹独立。

## 6. 学习率、权重与混合方案

本次复核 2000 局完成资产的 105 份文件均匹配，最终 `checkpoint-0.pt` SHA 为 `258feaa0505ba88a1fc950542bdee61a6f97678b2429b52634fccb6b90d523cb`，globalStep 201251，累计样本 1,610,008。模型 1,966,910 个 FP32 参数，AdamW β=(0.9,0.999)、eps=1e-8、weight decay=1e-4、有效 batch=8、clip=1；峰值学习率 3e-4，5% warmup 后余弦衰减到 3e-5，参考总更新 725,697。按保存公式计算该步下一学习率约 **2.63618e-4**，不能误以为已经衰减到 3e-5。

当前损失在 logits 上加固定 `softPriors`，policy 与 value 分别按有效权重分母归一，原生每原子权重 1。后续对照必须保持这个 prior 与候选全集，不同时移除 prior、改模型和改权重，否则无法解释收益。

**不建议给真人批次设置更高全局学习率。** 来源不同不改变共享参数的优化器归属；真人数量少、来源分布偏多人且含次优动作，提高全局步长会同时加大骨干和其他头的改动。AdamW 自适应矩估计下，样本权重也不等于线性倍率的学习率。官方更新公式见 [PyTorch AdamW](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW)。

示范学习文献支持“行为监督＋控制示范采样或损失贡献”，不支持本项目“真人一律更高学习率”的结论。[DQfD 原论文](https://arxiv.org/abs/1704.03732)通过监督项和优先回放利用少量示范；[DAPG 原论文](https://www.roboticsproceedings.org/rss14/p49.pdf)使用行为克隆初始化及示范辅助项。两者的任务和算法不同，不能直接照搬其系数作为本项目最优值。

建议的后续小规模方案：

- **起点**：等待既有 414 局工作结束、累计 2414 后，另立不可变实验目录，从同一个完成 checkpoint 克隆各臂；不更改当前续训任务或重置原日志。复用完整 AdamW/RNG 作为同源起点，另立精调学习率日程；不误用原 scheduler 自动覆盖新学习率。
- **学习率**：第一轮统一 peak=3e-5，前 5% 实验更新 warmup，余弦到 1e-5；其余 AdamW、batch、clip 不变。1e-4 只作为后续单因素对照，先不尝试超过原 3e-4。3e-5 是保守实验起点，尚无本项目最优证据。
- **来源比例**：战役未就绪时 policy 源混合 native/human=80/20；战役完成后再单独试 native/multiplayer-human/campaign-human=75/20/5。以固定采样窗口调度，报告实际原子数、宏数及总损失权重，不能只报名义比例。AI 席位单独隔离成可选消融池。
- **宏与父局均衡**：人类按父局／路线组采样、同组内按宏采样，每宏多个原子分摊总权重 1（1/k）。避免长局和 move+attack 相比单原子宏天然放大。先分来源再分父局，控制单作者／路线的重复曝光；native 端在第一轮保留原基线原子语义以缩小变更范围。
- **样本权重**：初始真人 q=1，对照 q=2。战役初始 q=1；65 elite 不默认赋 5–10 倍。低置信度来源采用 mask=0，不能用小权重掩盖不合法／状态未知问题。q=2 只作用真人 policy，不给回放 AI 席位或 value 加权。
- **实现陷阱**：当前 `pden=sum(weight*policyMask)`。一个全真人 batch 内全体权重乘 2，分子分母相消，完全不增加该批 policy 权重；在只含 native value 的批次里，少量 native 行的 value 又会被独立分母重新归一。应按来源分别聚合损失后显式设置来源系数，或确保混合批次且报告实际归一贡献；两个 worker 共享全批分母，只在协调端一次 AdamW 更新。不能分别按 worker 归一后再直接相加。
- **value 保持**：仅 native 可靠自然终局供 value 监督。真人 valueMask=false 并不冻结 value 头或共享骨干；为避免遗忘必须保留 native value 项及开发校准检查。若要冻结头，还需显式处理 AdamW 权重衰减，不能只设 mask 然后宣称参数不动。

示例显式目标：`L_policy=(1-α)·mean_native(CE)+α·mean_human_macro(CE)`，先试 α=0.2，再试约 1/3（对应在 80/20 基础上将真人相对权重从 1 提到 2 的归一目标）。value 仅在 native 上求均值，系数固定 1。这样采样比例用于预算，α 决定目标贡献，避免重复过采样再意外放大；如果采用当前全批加权均值，必须承认小批组成使实际贡献不等于名义 α。
