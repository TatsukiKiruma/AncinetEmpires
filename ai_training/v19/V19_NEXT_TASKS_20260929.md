# V19 接续任务：把单次 PPO 实验接成可验证的持续改进

日期：2026-09-29。先读 `V19_PROGRESS_REVIEW_20260929.md`。本文件修正旧执行报告的归因与依赖，沿用 `V19_LONG_TERM_TASKBOOK.md` 的最终20局合同，**不另开 V20，不重复已完成的准备任务**。这是后续执行指导，本次审核未启动下面的新训练。

终点不变：同一个纯网络SHA、原五图、冻结H0、每图两组新seed换边共20场，至少18次自然胜利；随后UI同权重核验。5/20、脚本完成、训练loss下降都不能写总目标完成。

## A. 修训练流程并完成一次小型集成验收（优先，建议2–4小时）

责任模块：`v19/training/ppo.py`、`value_warmup.py`、对应测试；必要的薄层轮次调度放独立模块。不改游戏规则、H0或UI布局。

1. **把行为模型、优势baseline和被更新模型的身份分开记清。** 默认采用采样时冻结critic：新一波先冻结完整当前模型，保存SHA，rollout记录该模型的logprob与value；PPO固定这批优势，不在epoch间改写old logprob。下一波必须从本次实际导出模型采样，critic也随它更新。
2. **价值预热移到新一波采样之前。** 若另做预热，只用之前的训练数据，冻结actor/trunk，验证策略不变后重新采样。不能在同批终局上拟合后直接回填同批优势并称无偏改进；也不能预热后仍读另一份模型的旧value却宣称检验了新baseline效果。不需要为了“完成预热”再次训练12遍；当前候选已经有critic，首轮可以直接采样。
3. **KL早停退出整批 actor 更新。** 在已测KL超限时不再做这次optimizer更新，跳出所有剩余epoch；若另训value，冻结任何会改变policy的共享参数。输出停止点、实际更新数、每轮和整批KL。阈值先保持0.02，不同时改LR和温度。
4. **独立价值验证。** 优先采用滚动验证：θk在新一波自然对局上的value预测必须在任何使用该波标签的更新之前落盘和评分，相对上一波训练分布拟合的常数比较，按map/phase/episode报告MSE和校准。若要用验证集选择critic checkpoint，再另按map×seed family固定holdout，两个座位及同局所有状态不能拆入训练/验证。旧训练内MSE改名为trainMse。
5. **保存能恢复的训练状态。** 除TS推理JSON，保存optimizer、已完成update、RNG、waveId和behaviorSHA。每批自动验证 `wave(k+1).behaviorSHA == wave(k).outputSHA`；显式value-only预热或rollback作为单独谱系边记录，不静默改起点。

集成验收必须覆盖真实控制流：预热前后策略相同但value不同，新rollout采到的是新value；第一次KL超限后update数不再增加，即使计划还有epoch；两波微型训练第二波使用第一波输出；保存恢复后下一批动作/RNG与不中断对照一致。原有公式测试保留，不用几十个形式测试代替这四件事。微型训练仅验机制，不记为80局棋力波次。

## B. 保住长局全程，建立最小失败诊断（建议2–4小时，可与A交错推进）

责任模块：`v19/env/subject_episode.ts`、`rollout/collector.ts`、训练加载器与独立回放工具。

- 用例如128/256条主体决策的块流式写出，连续编号，完成一块释放内存。完整保存到真实终局/真实截断；读取用mmap/偏移或块加载，避免一次读2.3GB再整体复制。分块是存储方式，不是强行结束游戏。
- `terminal` 只表示真实结束；若复用旧前缀作MC监督，用明确的 `mcReturn` / `recordCapped`，不再伪装该步终止。本轮主线优先新完整轨迹；旧前缀不当新PPO rollout反复重用。
- 保存双方动作与可恢复初态/规则身份，至少每个己方回合边界有快照；失败、截断和长局必须能重放到相同 actionDigest。给状态身份采用已有完整canonical state，不把当前粗 `stateHashOf` 当完整输入哈希。
- 采样队列按地图、seed、座位轮转；中断后只补缺失gameId，不从Duel重新采。落盘实际决策数、记录数、上限原因、回放路径。新seed分配器检查全局唯一；现有 `mapIndex*10+seedIndex` 不能扩到每图超过10seed后仍直接沿用。
- 做一个超过2000条主体决策的分块完整性测试，检查首尾、跨块GAE、重复/缺失编号和内存；不要为验收新存储再重跑全部旧实验。

失败诊断先覆盖最近候选与冠军的三条已变化DEV局，以及本轮候选其余失败/截断的回合边界；用原seed/SHA重放是诊断，不算新独立评测。每局给出首个可解释的严重失误、规则后果和替代行动完整己方序列→敌方回应。分类：经济/夺堡、招募出口/pending、路径/推进、战斗/反击、指挥官安全、收官/再招。没有可复核反事实时标“待验证假设”。

**不得以尚未8/20为由禁止失败诊断或短课程。** T19-06“16/20后的最后差距冲刺”不是早期诊断的前置门。

## C. 首个真实连续训练窗口（建议16–24小时，三波×80局）

先固定一个探索起点：建议使用已评5/20的34通道候选 `e999131c...`，它已经利用过新增输入。原P1继续作正式冠军；迁移P1 `1339764a...` 保留为回滚/对照，不能每波都自动回到它。任何起点变化写谱系和理由。

流程必须实际执行：

`θ0 → 新80局 → PPO → θ1 → 新80局 → PPO → θ2 → 新80局 → PPO → θ3`

每波5图×8个新seed×2座位，共80场自然开局尝试，全部保留在结果分母。引擎步数/墙钟上限沿用既有合同；非自然截断不假造终局奖励。新完整自然局进入主线；截断暂不参与终局MC梯度并报告排除率，若排除率明显增加则先处理收官/循环，不能假装数据已代表所有策略行为。

初始参数尽量沿用最近运行：LR2e-5、clip0.1、value0.5、entropy0.01、minibatch64、最多2epoch、gradclip0.5、gamma=lambda=1、KL0.02；变化只有已修正的执行流程和完整新轨迹。采样暂用已对账softmax T=1，部署DEV仍argmax。不要把γ或λ<1套到旧前缀伪终局上。

每波按顺序交付：采样完整性 → 更新前策略/value对账 → 新数据上的旧critic验证 → PPO → TS导出一致性 → 完整DEV20 → 下一波真实采样。默认只评本波最终导出；如需另评best，先声明选择指标与最多一份额外候选，不扫几十个时点。

允许DEV小幅波动而继续有限探索；正式冠军不动。出现非法/error/身份不一致立即修；DEV相对起点少≥3胜或截断≥5/20时，停止这条恶化链并查失误，显式回滚，不能继续耗尽三波预算。小幅退步不是自动重置每一波的理由。

三波是一个**上限明确的首次验证窗口**，不是保证能涨到8/20的承诺。240个新episode比“28k决策再多训练几遍”更有解释力。实际总墙钟以B修复后的吞吐重测；wave2旧环境约59自然局/小时，不含全部训练和评测，不能直接把80局采样时间当一轮总耗时。

## D. 用规则课程解决长程信用分配，最多选择一个主要修正

不等到M2。根据B/C最常见失败，选**一类**课程：例如“有城无兵的对手再招→阻断再招并清场”，或者“Icy水路推进与远程保护”，不要预设一定是温度问题。

- 从训练命名空间的可达快照出发，按原规则续弈，保存父局family和恢复阶段，不能重复发收入/恢复行动。
- 起步每波最多额外20个短课程局，五图正常开局80局保留；课程和正式分数分列，按episode和transition都报告占比。
- 可解短局用真实终局/有限精确续弈构造反馈；若蒸馏搜索偏好，证明行动序列确实改善，不用“整局换H0更强”替代第一手动作标签。
- 一类课程至少20个未见family/几何变体回归；涉及新特征时同步加TS/Python规则场景，先补具体失误所需的路径、pending或突击余量，不为一次训练预先重做全部架构。
- 如果训练局本身不会收官，先验证短局训练可学且未见变体提升，再带回整局；如果短局会、自然开局仍不涨，说明迁移尚未发生，不写模型进步。

长度分布先测再调：输出每局有效样本数、重复状态/输入率、前10长局的梯度样本占比、阶段覆盖。若长循环仍占绝大多数，可只试一次明确的分层/长度归一化对照；必须说明它改变了训练权重，不把“每局等权”当作标准PPO天然正确答案。

**温度只作有条件备选。** 要检验采样/部署差距，在同一冻结SHA、同一40个训练诊断局上配对比较T=1采样、argmax与一个预先规定的温度；所有结果保留，argmax仅是诊断臂。只有差异稳定且失败轨迹支持才改训练采样。实际选择分布必须在采样、old/new logprob、entropy和ratio中完全一致；不允许argmax加扰动后照抄原softmax概率。

## E. 晋升、扩展与停滞切换

| 触发证据 | 下一项实际工作 | 不允许的结论 |
|---|---|---|
| DEV较正式冠军至少+2（当前≥7/20），或到新里程碑 | 运行新FRESH40，候选和冠军同40局配对，共80场 | 仅DEV提高就替换冠军 |
| FRESH至少+4/40，无错误/回退，单图退步不超过2/8 | 暂定晋升；下一独立面板验证方向 | +4/40等于统计显著 |
| 已有FRESH改善并继续向M2发展 | 扩到累计6–12波；有效配方做42/1337/2026三训练seed，全部公开 | 先假定数据差十倍，盲目扩波 |
| 三波正确连续PPO及一次证据驱动修正仍停滞 | 对预先指定的一个候选做一次诊断FRESH40；无改善就冻结该配方并执行有限搜索试验 | 没到M2所以禁止备用搜索；继续同一数据加epoch |
| 两个新FRESH方向连续不改善 | 停当前配方，保留已确认最佳；下一步必须改变具体失败机制 | 只换评测seed赌晋升 |

停滞诊断FRESH候选选择提前固定：DEV自然胜最多；并列先截断少，再取较早模型。诊断面板一旦看过即退休，不反复选择“最幸运”的面板。统计汇总按map×seed家族处理两座位相关性。

有限搜索试验沿用T19-07：先40个训练窗口，固定总预算与单窗口上限；搜索范围覆盖“己方行动序列→敌方回应→下一己方决策边界”。搜索评价必须用可核验终局或在独立后继上通过检验的value；不把H0分数当胜率。取得动作级改进才扩200窗口、蒸馏到纯模型，再跑DEV与FRESH。搜索若不能改善，本试验据实失败；若搜索能赢而蒸馏不能，查表示/学习，不新增教师网格。

此时训练窗口可到发展阶段48–96小时，但只有已有复核收益才延长同路线。准备工程尽量控制在首窗口25%以内；超时必须列明阻塞机制、已产出模型与恢复命令，而不是新建一个版本重新写任务书。

## F. 最终20局与试玩交付

长期阶梯保留：DEV8→12→16→18只是里程碑，胜场必须由实际对局产生。M2约12/20时检查五图均能获胜；M3约16/20时针对剩余失败类型做至多三波纠错；不能只追Icy而丢Liberty。

若没达到，完整报告原20局，保持目标未完成；该面板退休，发生新训练/算法变化后才能申请新的封存验收。技术故障仅原seed/SHA重跑故障场。

通过后接入现有UI，不改布局；显示实际SHA/schema/策略，50个固定快照动作对齐，再经UI推理路径复跑同一20局核对摘要（这是部署一致性，不是新增独立胜率证据）。交付五图回放、模型卡、复现命令和原冠军回滚路径。
