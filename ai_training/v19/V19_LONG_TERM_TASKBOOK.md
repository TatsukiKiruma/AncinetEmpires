# V19 持续训练任务书：从5/20到独立18/20验收

**本文件是尚未执行的后继计划，不是完成报告。** 使用同一个任务书持续执行、记录调整和恢复位置，不因一次失败自动换版本重新规划。

## 1. 最终交付与成功定义

沿用既有目标：**同一个纯网络模型**，在以下五张原SD地图对冻结H0，每图两个新seed、每seed交换模型座位，合计20场实际对局，取得至少18次自然胜利。

- Duel、Icy Paths、Liberty Port、Mourningstar、Crossed swords。
- 各图4场，共20场，不能拿一场的两个视角当两场模型对局。
- 自然胜只认引擎 `winnerAllianceId == candidateAllianceId`。平局、时间/步数截断均不算胜；全部20局都须执行完并有终止记录。
- 不改地图、收入、兵种、胜负条件、H0、合法动作过滤来提高成绩。正式推理只用网络和原生合法动作；训练期间的搜索或课程单独标识。
- 正式20局只加载一个冻结SHA；不按地图换权重，不使用H0静默兜底，不从多次验收里挑最好的20局。
- 交付同一SHA的模型卡、逐局回放、逐图/先后手分解、UI加载与身份验证。18/20是约定样本验收，并非所有地图/对手总体胜率90%的统计保证。

在18/20之前，只能报告“某阶段完成”或“模型改善”。总任务不能写COMPLETE。

## 2. 路线选择与解除旧依赖

主线确定为：**补齐输入 → 修好真实结果训练接口 → 小规模规则课程与价值预热 → 当前策略采样的PPO → 五图连续改进 → 独立验证 → UI同权重验收**。

H0动作模仿只作初始化和短期稳定辅助，不再担任整条路线的唯一目标。B100保留为可选候选提议器，不必先证明它强于H0才能启动PPO；也不必先做第二次已无依据的H0蒸馏。

PPO被选为首个结果驱动实现，是因为它直接用新策略对局的回报更新策略，能复用现有合法动作打分网络；不是因为论文能保证本游戏18/20。依据：[PPO原论文](https://arxiv.org/abs/1707.06347)。从当前策略重新采集经验的必要性也与序列决策的分布偏移相符：[DAgger原论文](https://proceedings.mlr.press/v15/ross11a.html)。

搜索改进/专家迭代作为**已有明确切换条件的备用路线**，见T19-07；不与主线同时大规模扫参。依据：[Expert Iteration原论文](https://arxiv.org/abs/1705.08439)。

保留旧冠军作为回退点。允许阶段实验失败，但每次失败必须说明改变了哪个假设，不能只增加epoch或换一个seed继续相同配方。

## 3. 贯穿全程的评估与进度规则

### 3.1 三类对局面板

| 面板 | 用途 | 构成 | 使用限制 |
|---|---|---|---|
| DEV20 | 纵向筛选与查回归 | 沿用已反复使用的20局 | 可以反复看，但不当独立泛化证明 |
| FRESH40-k | 每次候选晋升复核 | 五图×4新seed×换边=40局；候选与旧冠军各跑同一40场 | 命名空间与训练、前次复核分离；完整逐局对齐；看过后退休为开发集 |
| CONFIRM20-k | 唯一正式交付验收 | 五图×2未使用seed×换边=20局 | 冻结模型后才运行；不可用于检查点挑选 |

FRESH40不必等到18/20才运行。DEV20比当前已确认冠军多赢至少2局，或首次到达下一个阶段门槛，即可申请这一轮复核。每个训练波最多两份预先规定时点的候选进入完整DEV，避免几十个检查点选最好。

工程晋升规则：FRESH40候选至少比旧冠军多4胜，非法/回退/错误为0；任一地图相对旧冠军退步超过2/8则先查原因。**+4/40仍不自动等于统计显著**，报告按map×seed家族配对差和区间；下次独立面板方向复现后标记“确认改善”，首次仅标“暂定改善”。

固定地图开局本来就可重复：新seed不是新地图、新初态几何，也不会保证网络开局输入从未见过。状态级独立诊断需要去重；对局级独立性要求随机流、训练用途和家族隔离。这两种含义不能混用。

### 3.2 棋力里程碑

以下是推进门槛，不是对模型未来成绩的承诺，也不强制每个训练轮恰好增长若干胜。

| 阶段 | 希望看到的DEV20变化 | 必须伴随的证据 |
|---|---|---|
| M0 正确性 | 仍以5/20为起点 | 新表示能区分反例；结果接口正确；不宣称胜率进步 |
| M1 首次可见改善 | ≥8/20 | FRESH40比旧冠军至少+4；不再只有旧图受益 |
| M2 能与H0竞争 | ≥12/20 | FRESH40≥24/40；五图各至少2/8；三训练seed完整公开 |
| M3 稳定占优 | ≥16/20 | FRESH40≥32/40；五图各至少5/8；Icy/Mourningstar不再长期零胜 |
| M4 候选冻结 | ≥18/20 | 新FRESH40≥36/40；五图各至少6/8；胜率/时延/回退合同通过 |
| M5 用户验收 | 正式CONFIRM20≥18胜 | 同一SHA、全部20局、每图4局、自然终局、可回放 |

M4的36/40是本计划的额外稳定性筛选，用户原目标仍是最终18/20。没有达到中间门槛时保留实际成绩，不能把“离线准确率提高”填进胜场列。

报告固定列：冠军/候选SHA、上次确认胜场、本次DEV、FRESH、逐图、先后手、截断、实际训练新对局/新输入/更新数、用时、下一步。文件数量和脚本数量不进入进步指标。

## 5. T19-01：补齐可学习的状态表示

依赖：身份固定。目标：先解决已经复现的信息缺失，避免再做仅改变容量的宽泛网格。

实现一个新schema，保持历史schema和历史权重可独立运行。表示、规则派生量与模型结构分别放模块，不放进UI。

必须补齐：

- 双方明确兵种身份；敌我单位有效攻击、物防/魔防、HP与最大HP、等级和距离升级阈值的经验。
- 实际移动余量、当前移动/行动/突击后移动、已受支援标志、pending具体单位及堆叠招募阶段；不能只有“有pending”一个布尔。
- 状态类型与持续期、墓碑位置/剩余期；治疗超额HP不能被截断到1后丢失。
- 地形实际移动/回复/防御信息、城堡与城镇独立分布、可招募出口和下回合收入。
- 将“当前剩余行动威胁”和“下一敌方行动阶段潜在威胁”分开。后者按真实回合开始状态重置及合法路径/射程构建；多敌军位置相互作用不能假称为精确必杀概率。
- 候选关系特征：真实路径到可占领目标的距离变化、移动后合法攻击机会、落点暴露与己方指挥官危险、招募占位。只编码可核验规则，不把H0总评分或地图ID当替代答案。

优先保留现有32通道、2残差块骨干与候选打分形式，扩展输入通道/语义并增加少量关系量。全图关系仍不足时才试一个带位置关系的注意力模块；V18无效的GAP不再作为首要实验。

迁移：保留旧输入通道原义，新通道的stem权重与新policy列置零，使初始函数尽量保持。**不能一边改变旧ch21威胁语义，一边声称零初始化保证logits不变。** 新的危险信息用新通道，旧通道仅作兼容。新增表达能力需要后续训练才会使用。

验收：

1. 本次史莱姆/水元素反例可区分；下一敌方回合威胁反例修复。
2. 至少120个规则场景，覆盖六类：夺城经济、招募/pending、射程/反击、状态/恢复、支援/突击、清场再招。TS/Python同输入同schema的张量和候选映射一致。
3. 200个真实快照对齐TS/Python logits及argmax，候选重排语义不变；零初始化迁移的数值误差和选手变化如实记录。
4. 单步时延按五图实测，沿用已有1秒交互预算作为上限；批量训练编码可缓存，正式运行不能隐含搜索。

这些通过只表示输入可用，**不要求先提升DEV才能开始PPO**，否则又会形成前置死结。

预计工程1–2工作日；超过此范围仍不能通过时先定位最小正确表示，不能无限扩schema。

## 6. T19-02：真实胜负训练环境与采样通道

可与T19-01的编码工作交错推进，但不在接口未过测试时启动长训练。

创建训练专用包装层，继续调用同一个权威TS引擎，不重新实现一份Python游戏规则。建议模块边界：`v19/env/subject_episode.ts`、`v19/rollout/collector.ts`、`v19/training/trajectory.py`、`v19/training/ppo.py`、`v19/eval/`。

首版仅训练一个主体座位，对手固定H0；每局随机但均衡交换座位。每条训练transition从主体一次决策到下一次主体决策，中间若轮到H0就推进其全部动作。主体连续移动/攻击仍属于同一方，不翻转价值符号。

必须记录：输入schema、模型SHA、合法候选码顺序、选择动作、行为log_prob、value、reward、真实currentPlayer变化、终局winner、terminated/truncated、family/seat、RNG身份、编码耗时和推理耗时。

奖励/回报合同：

- 主体自然胜+1、自然负−1、自然和0；未终局0。
- 不使用engine累计的dense reward，也不使用Env的超时金币/军力判胜。
- 首版完整局gamma=1，使同一自然胜利不因原子动作多而被指数衰减；GAE等估计方法另有参数，但不得把每个原子step等价于敌我交替。
- 自然终局bootstrap=0。采样批次截断保留可恢复快照，或使用独立标记的critic bootstrap；不存在真实winner时禁止写终局z。critic尚不可靠时优先续完短局，不伪造监督。
- 对手吃掉主体最后单位、引擎自动换手、双方无兵/有城、指挥官死亡再招等都必须覆盖。
- 合法动作过滤与正式推理一致，mask后概率重归一；动作永远按语义码对齐，不能混用旧数组索引。

验收：至少12个手工可核算的短episode，精确核对回报、log_prob重放、GAE符号、终止mask；一批数据更新前ratio应约1；至少一次结果优势梯度确实改变policy参数。再跑20个真实短采样局验证恢复与记录。将 `winner=null, reward=-1` 的现有截断探针纳入负例。

性能pilot：采样30分钟，分别报告环境转换/秒、网络决策/秒、完整自然局/小时、数据写盘开销。当前Python是CPU版，不预设有CUDA。使用多个持久Node进程与批量推理，先在2/4/8采样进程中选一个实测合适配置，避免PyTorch线程过量竞争。IPC批量处理、编码复用优先；**不为提速削减合法动作或改规则**。

交付：可运行且经短局验证的训练接口、性能报告。性能优化只允许一轮有profile依据的改动，之后进入训练，不让优化工程取代训练。

## 7. T19-03：规则课程与初始化，最多一轮短模仿预热

依赖：新编码和训练环境通过最低正确性验证。

课程按真正影响胜负的技能组织：

1. 终局清场：敌方无兵有城、无城有兵、指挥官可再招；把优势走成自然胜利。
2. 战斗交换：不同物魔防、最小射程、反击、升级、致盲、集火与支援。
3. 招募出城：新预算450/500/550、普通单位挡堡、堆叠pending、新兵后续动作。
4. 地形推进：水路、桥口、绕行、保护远程、指挥官夺堡。
5. 经济开局：占镇/夺堡时序、未来收入与当前战损平衡。

人工场景只作规则诊断和早期课程；正式胜率仍从原五图自然开局测。课程样本优先来自新采集的可达快照，胜局和败局都有，不能只按旧轨迹已知自然终局筛掉难局/截断局。所谓“均势”同时检查军力、HP、经济、建筑和指挥官状态，不再仅以单位数量差≤1代替。

行为预热限500–1,500更新：新schema编码；若使用H0标签，统一新版L1单次评分合同，注明它是行为目标。相同输入的多种合理行动可用明确多目标/分布监督，不强逼拟合随机抖动。不能把S3的整局策略优势写成第一手动作优劣。

验证至少覆盖五图×三个阶段×H0/学生来源；同一family不跨train/val；开局未见输入每图至少20，总计至少100；共享固定开局回归另列。断言trainer消费的manifest就是该版本，缺桶使“覆盖验收”失败；共享输入不得作为未见验证。已有V18开局探针按家族来源重新选择后可复用。

价值预热用自然胜负，按map/phase/family均衡；报告相对常数、分桶校准和样本数。**critic作为PPO方差降低器不需要先通过搜索后继排序门**；只有它接入搜索时才检验后继排序。

交付：课程训练前后结果、一份初始化checkpoint、完整DEV20。没有提升也可带着正确的初始化进入结果训练，不重复三轮H0蒸馏。

## 8. T19-04：真正执行PPO首轮循环

目标：形成第一条可以持续增加自然胜场的训练链；不以“PPO代码写完”验收。

首个配方固定如下，属于启动值，任何调整必须有曲线依据并写新run：

| 参数 | 首版 |
|---|---|
| 初始化 | T19-03模型；保留P1回退 |
| 对手 | 全部H0，座位均衡 |
| optimizer | AdamW，LR=1e-4；发生明显KL超限时再降3e-5 |
| PPO clip | 0.1 |
| value loss权重 | 0.5 |
| entropy权重 | 0.01，按合法动作数量同时监测归一化熵 |
| rollout优化 | 每批最多4个epoch，minibatch64，梯度裁剪0.5 |
| gamma / GAE lambda | 1.0 / 0.98；完整episode测试回报符号与mask |
| KL停止 | 同一批近似KL>0.02停止继续重复优化该批，重新采样 |
| 模仿辅助 | 首版无强制旧冠军KL；如需辅助CE，只作预热，不用失败动作持续锁住policy |

每一波冻结行为checkpoint，采集 **80场新的完整五图对局**（5图×8seed×2座位）及相应课程局，全部标记实际SHA。episode上限沿用正式规则；截断不伪造结果，也不从分母删除。记录实际主体决策数，不能把“80局计划”报成80局完赛。批次切片需保证同局后半段可续接。

一波完成采样→更新→导出→TS推理校验→DEV20；下一波必须由更新后的checkpoint采样。初始最多三波、240个全图episode；每波额外课程局不超过全图局数。

起步课程混合：50%原图自然开局、30%可达中盘、20%短残局，明确各自episode和transition比例。达到M2后自然开局≥70%，达到M3后≥90%；最终评测100%自然开局。课程胜率不混入正式分数。

每波记录：episode自然完赛比例、终局胜率、value校准、policy/value实际梯度、KL、entropy、clip fraction、loss、平均决策长度、逐图先后手、更新前后对战胜场。探索策略采样与最终稳定argmax分开报告，DEV以最终部署选择方式为准。

验收交付：至少一个真实PPO采样更新循环和完整五图DEV；优先争取M1。若三个循环仍未产生候选复核改善，进入下面的诊断决策，**不是再次把结果训练标“后续待做”**。

## 9. T19-05：有依据地调整训练，推进到M2/M3

|---|---|---|
| 规则课程都学不会、表示碰撞仍在 | 先修输入/梯度；只试一个关系注意力增强 | 已知反例和未见几何场景通过，再比同预算DEV |
| train提高、未见场景退化 | 增加新family、降低每批重用、平衡重复输入权重 | 新输入/家族增加；验证与完整对局同时改善 |
| entropy快速塌缩、KL突增 | 降LR/每批epoch，保持明确探索分布 | 动作分布恢复、自然胜场恢复；不靠只调温度美化离线分 |
| 很少完赛、残局不收官 | 增加原规则下的短收官课程，分析城堡再招/堵城状态 | 截断率下降、自然胜局增加；不把截断改成胜 |
| 短局会下、开局仍崩 | 增加完整开局和更早可达中盘；检查经济/指挥官路线 | Icy/Mourningstar胜场、前期收入差和指挥官存活改善 |
| 一图变好其他图退化 | 分层采样、保留其他图的新鲜episode | 五图各自FRESH成绩，不能只看总分 |
| 搜索能赢、蒸馏后不能赢 | 只从真实受益的状态动作蒸馏并与PPO互补 | 搜索/纯模型单列；纯模型闭环也增胜 |

前两轮任一配方有复核改善后，扩到总计6–12波（每波80全图局，即480–960局/训练seed，另列课程局）；只有实际达到M2附近才继续扩大。波数是预算范围，不能提前承诺这些局数足够达标。

有效配方再做seed42/1337/2026三次优化/采样重复，全部从同一声明初始化开始；这不是三个独立预训练模型。每seed评完整DEV及至少一个新复核面板，完整列出结果，不只公布最佳seed。

到M2后可做一项对照：80% H0 +20%旧冠军/已晋升历史模型作为对手池，防止只依赖一条H0轨迹。主要目标仍是固定H0；对手池若损害该目标，不强行保留。无需为“自博弈”这个名称单独扩项目。

训练状态与冠军分开：探索中的候选允许回退，正式试玩只更新已复核冠军。连续两个新FRESH面板没有改善，冻结该配方，保留最好模型；禁止同数据加到16k再声称新路线。

## 10. T19-06：针对最后差距，推进到18/20

进入条件：M3附近已有经过复核的16/20级候选，而不是从当前5/20直接宣称进入冲刺。

对最近两个开发面板的所有失败/截断保存完整轨迹，按以下规则关联诊断：招募/经济、真实路径、指挥官暴露、战斗顺序、状态/支援、收官。不能只看首次教师分歧。

在训练命名空间重新采集同类局面，不回流封存验收局。对每个候选修正，检查一段完整己方行动及敌方回应；单动作、同一固定H0续弈没有区别时，不用更多相同噪声样本强造偏好。

数据仍保留至少一半来自全部五图的当前策略正常对局，另一半可偏向失败类型。此比例按episode和不同输入同时报告，禁止4,133条重复行再次冒充新覆盖。

每个失败类型至少能指出：实际规则后果、可改变的策略行为、独立同类局面回归、整局胜场是否改善。总计最多三波专项调整，每波一个主要假设。模型达到M4后立刻冻结，停止针对DEV继续微调。

## 11. T19-07：备用路线——整回合搜索改进与蒸馏

触发：结果接口/输入已正确，至少三波真实PPO及一次有依据的修正仍无FRESH改善；或PPO已到平台且搜索在同类可解局面产生可复核优势。**不要求先证明B100必强于H0，也不无限等待“≥60个决定性配对”。**

仅做一个有限试验：

- 复用引擎，搜索单位覆盖“当前己方行动序列→敌方实际回应→下一己方决策边界”；不把搜索深度3个原子动作误认为3轮敌我博弈。
- 根部保留当前policy高概率动作、必要战术动作和少量探索候选，明确搜索覆盖集合。H0/B100只提议，不把它们分数称为胜率。
- 价值函数只在独立自然后果/可解残局的后继排序与符号测试通过后作为叶估值；未通过则先用可解短局精确结果，不要求所有早期训练都等待它。
- 先40个训练窗口，每窗口有限预算，固定总窗口数和最长耗时；报告决定性配对的实际数量，不能一直采到p<0.05才停。
- 必须记录搜索异常/回退，禁止 `catch -> H0` 后仍算纯教师。
- 有明确行动级改进后再扩到200个窗口与访问分布/动作偏好监督；至少一次蒸馏后的纯模型完整DEV和FRESH检验。

如果更强搜索本身无法在独立面板产生优势，应报告搜索试验失败，不能把同样的教师硬标签覆盖全池。若搜索强而网络学不会，回到表示/数据覆盖问题。该分支本轮最多一套搜索配方，不再复制V16/V17教师参数网格。

## 12. T19-08：最终封存验收与实际试玩

进入：DEV≥18/20、最近独立FRESH40≥36/40且逐图门槛通过。冻结checkpoint、规则、H0、动作过滤、推理版本、正式seed清单和每局上限。

1. 运行全部CONFIRM20。每图严格4局，输出自然胜/负/和/截断、双方座位、SHA和完整可复现轨迹。
2. 满足18次自然胜利且无非法/隐藏回退/运行错误，标记最终样本验收通过。技术故障只允许按原seed原SHA重跑故障场，不从正常败局中挑局重跑。
3. 未通过：完整报告成绩，将本面板退休为开发信息；保持用户目标未完成。下一轮必须先有新训练或明确算法变化，再冻结新的CONFIRM namespace，不连续抽seed赌18胜。
4. 将通过的唯一模型接入现有UI；保持布局，仅在已有调试/策略信息处显示实际SHA/schema/策略。UI与arena在50个固定快照上动作一致、无回退，再用UI推理路径跑相同正式20局核对动作摘要；这属于部署一致性复验，不称为新的独立20局。
5. 提供五图回放入口、模型卡、旧冠军回滚路径与复现命令。

## 13. 预算、恢复与不能再次发生的停工方式

本计划不启动云算力、不预设机器有GPU。当前环境为CPU版PyTorch，后续是否增加算力应由真实吞吐决定。

V18冠军20局累计耗时约0.42小时，U/K约0.63/0.79小时；这是逐局耗时求和，**不是并发墙钟**。搜索教师和失败拖延局贵得多。正式预算按T19-02的pilot重新计算：

`预计墙钟 = 计划自然完整局数 / 实测完整局每小时 + 训练更新耗时 + 候选与冠军复核耗时 + 20%余量`。

建议以连续可恢复的多个阶段预算推进：

| 阶段预算 | 主要交付 | 到点怎么处理 |
|---|---|---|
| 工程准备1–3工作日 | 表示、结果环境、规则课程、短训练确实运行 | 明确阻塞和恢复命令；不能标训练完成 |
| 首次训练窗口24小时 | 尽量完成三波真实PPO与对应DEV，争取M1 | 若吞吐不足记录实际完成量，先做一次profile改进；不伪报计划局数 |
| 发展窗口48–96小时 | 有效配方扩展、三seed、M2/M3复核 | 仅有胜场改善才延长相同路线 |
| 冲刺与封存窗口24–48小时 | 剩余失败类型纠错、FRESH、CONFIRM、UI核对 | 未到18/20则任务未完成，保留最佳结果 |

以上是待pilot校正的资源规划，不保证数日内一定达到18/20，也不是本次已获授权启动的训练时长。计划本身完整到验收，执行者无需每个小阶段重新要求用户再下一个版本的任务。

准备工作应尽量控制在总预算20%–25%，采样和实际训练约50%–60%，复核/正式对局约20%–25%。正确性问题可以阻止错误训练，但要具体定位；不能把预算全部花在增加审计脚本。

每波保存模型、optimizer、RNG、rollout游标、已经消费的family、下一条可运行命令。预算用完写 `BUDGET_EXHAUSTED / OBJECTIVE_NOT_MET`；连续无收益写 `RECIPE_STOPPED` 并执行已规划的调整/备用分支。**“第二轮没做所以强化学习不能做”“合同写完所以任务完成”“没有18胜所以连中途复核也不跑”这三种停止理由不再允许。**
