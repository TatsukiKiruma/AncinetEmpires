# 定向合法动作缓存提速计划

R3扩展面板中途p95接近600ms，当前实战代码继续冻结。检查发现GameEngine只缓存无query的完整集合，单军威胁与三军集火反复调用同一引擎初态、相同unitId/skipRecruitment的定向查询；step合法性也可能重新运行相同权威查询。

计划在R3资格及40局教师采样/打包结束后，仅扩展状态级缓存，不改变规则、候选顺序、特征、模型、搜索预算或评分。若R3硬门禁失败，则在新完整资格版本中验证；不得将新旧源码混在同轮计时。

- key完整包括playerId、unitId（严格区分undefined与null等非法类型）及skipMovement/skipRecruitment/onlyAttacks。只缓存普通数据对象中的合法已知字段；原型对象、getter和其他输入直接调用原权威函数，保留其语义。
- 执行step内部中间态不缓存；合法step/reset失效；初态相同的clone共享私有缓存，外部动作数组和坐标独立复制。缓存对象与GameState也应隔离。
- 不从完整集合手写过滤规则，所有缓存首次值直接来自原getLegalActions。step校验可只读复用同一私有查询结果。
- 应增加返回值改写隔离、clone/step/reset时序、混合参数/非法类型/原型查询与环境mask回归；与立项前参考引擎对照多状态全部定向查询，并重跑完整轨迹/编码差分。
- 在数据与数值差分通过前不应用公共改动。性能最终在无训练并发的完整四臂同面板验证，不把并发训练时的微基准当正式门禁。
