# 全量数据接收与后续训练替代实施计划

日期：2026-10-16，Asia/Shanghai。本文替代 `next_stage_research_20261015/PLAN.md` 中的训练留出、封存现有地图和仅转换双人主线安排；旧研究报告保留为历史证据，不回写。本计划受本轮授权约束：开展数据接收、严格验收与紧凑产物准备；**不启动模型训练、昂贵搜索标注、新对局生成、部署或晋升，不操作手机采集。** 独立评测本轮只制定协议。

用户已确定产品顺序：先提升**双人 SD、当前电脑浏览器**的实战能力；三四人及其他合格模式也应转换验收、分桶保存，首个双人模型不直接混入这些桶。

## 1. 对旧方案的明确替代

1. 当前原生 3000 父局及全部真实抓取回放逐项进入接收队列；**所有通过对应门槛的数据均登记训练用途**，不做 70/15/15 数据留出，不封存现有地图，不因已被研究或旧评测消费而剔出合格训练材料。
2. 训练资格按记录、标签用途分别判断，不以“整局通过/不通过”替代细粒度依据。合格动作可以有 policy 资格而无 value/return 资格；没有自然结果不妨碍完整、合法、语义明确的行为学习。保留所有原始档案和拒收证据。
3. 全量接收不代表全部记录等权，也不代表立即把三四人、SO、不同奖励视角混入同一模型。分桶、血缘去重、长局降权、来源标识属于训练组织；不得用固定 reservoir 替代全部合格数据，再宣称“全量使用”。正式训练采样协议应保证每个合格父局可访问、记录真实覆盖和零暴露原因。
4. 现有数据可以用于拟合诊断、训练损失监控和错误回归；这些指标全部标注“训练内诊断”，不能称独立开发或最终验收。后续开发/最终评估另建全新父局，且不得再把它们用于本候选训练。
5. 若预算只完成部分转换，明确写“全部已入队、已接收 X、隔离 Y、待处理 Z”；不把待处理当合格，不以磁盘不足为由删除源数据、静默跳过多人或缩减全量目标。

机器验收合同见 [ACCEPTANCE_PROTOCOL.json](ACCEPTANCE_PROTOCOL.json)，新评测协议见 [INDEPENDENT_EVAL_PROTOCOL.md](INDEPENDENT_EVAL_PROTOCOL.md)。动态采集数字、验证前沿、续跑终局覆盖均引用主代理在本目录另行冻结的一致快照；本文不把 10 月 15 日的轮次和自然结束计数冒充实时状态。

## 3. A0：冻结来源、接续图和资源（本轮）

先保存 git 状态与当前源码依赖身份；不修改公共规则或历史资产。双读动态 status/outcomes/chain/policy 和源索引，核对 SHA、mtime、业务版本、段尾 final 与下一段 initial；不一致时只读取重试，不操作采集器。读出的原文件副本与统计必须绑定同一 snapshot_id。

为每个原始父局建立有向段图；父局内检验动作全局序号、AI seed 连续性、累计动作数、快照边界、归档与已存在原生链验证凭据。共享已验证前沿之外一律 pending，不能根据较新的 status 单独释放。终局覆盖以同一冻结快照下最新**已验证**末段结果为准；原始 3000 局封存验收不回写。

区分 `natural_terminal`、`verified_surrender_terminal`、`unfinished`、`sampling_truncated`、`confirmed_cycle_stop`、`invalid`。s2466 的循环停止不是自然和局或指定胜者；其全父局 value/terminal-return 标签保持 mask，确认循环尾部不作正向 policy 示范。其他长局不得因步数多或完整状态不重复自行判和/判胜。

产物：来源目录、父段图、段验证前沿、终局覆盖账本、旧评测/预训练谱系消费账本、资源预算与隔离代码表。每条来源均有 `pending/accepted/quarantined/duplicate_alias` 状态；整批计数可核对到全部输入。

## 4. A1：读入、展开与 strict 转移（本轮，分批）

模块按单一职责拆为原生帧读取、原生规则语义投影、宏动作展开、权威 TS 引擎校验、来源标签、紧凑写入器。优先复用权威引擎；Python 统计不得另写棋规。所有输出指向本次目录或明确的新阶段目录，不运行默认覆盖历史路径的旧脚本。

先用覆盖夹具验证：BE int32 帧长度、完整对象消费、未知枚举/null/边界、当前玩家与联盟、初次收益、克隆、复合移动与攻击、真实移动余量、招募 pending、召唤/治疗/支援、淘汰自动换手、投降/自然终局。双人主线夹具先通过；三四人及 SO 也建立各自夹具，不把它们当只读反例而永久不接收。

随后将**全部来源**按确定顺序排队，双人 SD 优先处理，三四人 SD/SO 等桶跟进。每条释放 policy 记录必须精确还原唯一动作展开、在完整有序合法候选中唯一映射、strict 执行并比对承诺字段。forced、跳步、first-match、丢失字段或忽略通知都不能使其通过。全量 strict 尚未完成的记录留 pending，局部已证明缺陷进入 quarantine。

共享初态错误、联盟映射、收入或宏展开系统性差异会阻断整个受影响规则桶；可独立证明的局部损坏只隔离受影响记录/后缀。若损坏后不能从可信完整快照重建状态，则不能继续接收下游记录。修复须产生新解析/规则身份和新凭据，不篡改历史验收结果。

产物：逐局/逐段接收收据、全量覆盖索引、逐动作或区间失败代码、原始到规范动作映射、待处理账本。通过率仅作统计；“99% 成功”不能把剩余 1% 自动放行。

## 5. A2：policy、value 与 return 分开释放

|用途|必须满足|未知结果与失败处理|
|---|---|---|
|policy 行为目标|来源/玩家归属可信；状态可重建；动作唯一且 strict 合法；完整合法候选/编码无未决信息损失；来源风格可追溯|未结束仍可接收；不声称动作最优。确认循环尾部、纯投降诊断、歧义/丢失信息片段隔离该用途|
|value 自然结果|全部 policy 状态合同；结果类型和真实胜者联盟经原生语义与配置核对；末段覆盖已验证；从 actor/联盟视角生成标签|unfinished、采样截断、循环停止、未知赢家全部 mask；TS 重建终局、房间 CLOSED 或字段名 winner_mask 单独不足以放行|
|value 投降结果|可靠投降者/被淘汰者、规则与终局赢家明确；独立标注 surrender 原因|单独 target_kind/桶，不混称自然结果；不证明客观局面必输，多人投降未结束不产生终局标签|
|return / TD 目标|连续真实转移及 actor 时间尺度明确；奖励版本、折扣/持续时间、终局/截断/bootstrap 资格冻结；每个边界无缺步和双计奖励|本轮默认不释放一般 return。未知尾部无真实 bootstrap 就 mask；代理 reward、timeout done 和自然胜负不可互换|

原始 `winner_mask` 保留 raw 字段；投影明确命名并绑定本次 APK 原生玩家状态 h 的语义证明，不按“mask”猜位掩码或玩家 ID。多人以联盟映射生成每玩家视角，不因自己未被消灭就标胜；平局只有规则/原生证据支持时才允许。

宏动作若展开 k 个原子动作，policy 的宏级总权重保持 1（或另行预注册权重），不因展开倍数放大该行为。return 如按原子时间定义，记录 k 及折扣积；如按真实玩家换手或 option 定义，明确决策边界和持续时间。奖励不能复制 k 次；不能每个原子步简单取负价值，只有对应玩家/联盟视角切换才应用正确映射。

## 6. A3：输入、有序候选与紧凑产物（本轮以证据为限）

完整规范状态、网络输入、有序候选三层身份分别保存。网络无须塞入 UI 无关字段，但所有影响规则或后续决策的观测别名必须形成证据和资格限制。优先核对经验/状态计时/真实移动余量/墓碑/pending 来源、堆叠和多人 owner/下一行动者。旧研究已核对当前 20 图最大 19×19，没有证明本批发生 20×20 裁切；新地图仍检验尺寸。

三四人旧编码会合并联盟/敌人，不能因当前动作能表示就认定完整多人输入合格。允许把其完整状态/动作的已验收紧凑记录分桶保存，标 `state_transition_accepted=true`、`model_schema_eligible=false`；后续 schema 通过才解锁对应训练，不丢弃数据，也不直接混进首个双人模型。

完整候选 actionCode、顺序双射、mask、tie 和投降合同统一；不得候选采样训练却隐瞒部署使用全候选。涉及新 schema/网络迁移时，至少 1000 个分层状态比较 TS/Python 输入、候选序列、全部 logits/value/argmax，阈值沿用登记合同，不为失败放宽。当前没有完成新前向则如实标 pending，不声称已生成可训练张量。

紧凑格式保存可重建状态引用/周期检查点、原始动作引用、规范索引、候选摘要与验收侧车，按需编码；不全量 dense 导出 34×20×20 FP32。每个合格记录最终都在训练目录可访问；去重通过 alias/权重归并，不删除原始身份。原生与真实回放、双人/三四人、SD/SO、自然/投降/未知、正常/专项初态、真人/电脑席位分别标记。

本轮产物状态分开：`接收合同已完成`、`源数据已盘点`、`全量 strict 已完成`、`compact 全量已完成`、`model schema 已完成`；任何一项 pending 都不得概括为“所有数据已可训练”。

## 7. 后续 T 阶段：全量合格数据的训练使用（本轮不启动）

先锁定某次 data_release，首个产品模型读取**全部合格双人 SD**训练记录；三四人/SO 合格桶已保存但不直接混用。按父局、地图、场景、座位、真实回合和事件分层调度，长局/重复尾部降权，稀有兵种/技能可提高事件采样率；总权重受父局预算控制。正式消费台账列出各合格父局/记录曝光数，不能用数百万相关动作冒充独立样本。

保留旧推荐的可证伪路线：相同新状态上，原生行为 N 与 Heuristic 标签 H 来源受控对照；真实抓取可作为来源明确的 M 对照，保持总暴露预算。若只做部分训练数据小试，标明是临时训练配方探针，不改变全部合格数据的训练归属；正式拟合阶段应覆盖全部可用双人 SD 训练桶。无现有留出，训练内 Top-1/loss/结果校准只能发现合同与拟合问题，候选筛选依赖后续新开发父局。

value 独立支线只有标签资格通过才加；离线 RL/在线 PPO 后置。R8 Top-1 改善未转化为稳定棋力，R10 同父局长链可学但无新父局收益，R12 有限 Heuristic 接管仅 1 家族合格且 0 更新，不能通过扩大更新或介入时长把失败路线包装成新方法。搜索教师须先在全新训练用途父局、匹配总预算下证明资格，再标注蒸馏；此类新训练父局必须登记进训练谱系，禁止后用作独立评估。

先单 seed 有界试验、固定更新与训练内选模合同，再按真正新开发父局的预注册门槛决定第二 seed/正式训练。最终仅打开预选配方，不能按结果追逐 seed、延时或追加比赛。具体独立性及成功标准以单独协议为准。

## 8. 磁盘、计算与停止条件

**本轮整个新目录的 compact/索引/临时解压/收据累计新增上限为 1.25 GiB，C 盘保留至少 12 GiB。** 启动每个可写批次前测剩余空间并预留尚在后台采集的增长；容量采用预计峰值而非最终压缩大小。临时文件也计入预算，不得额外复制源包。只暂停自己的验收/写入，不停止手机，不改采集队列或控制文件，不删除历史模型、源包、数据和归档。

全量原生验收的 CPU 时间、动作展开倍数和紧凑存储量目前仍为估计，先测有代表性的每千宏动作字节/耗时及最坏段，再外推全部来源、人数桶和后续验证前沿。1.25 GiB 是本轮输出约束，**不是全量最终训练包必须塞下的硬约束**。估算超过预算时保留全量目标、提交 pending 清单及测量依据，等待后续另定存储目录/空间和批次预算；不得以压小输出为由丢字段、删除数据或把未转换数据判坏。

## 9. 后续独立评测与交付门槛

现有 3000 局及全部抓取的合格数据不再保留测试集，评测必须来自**后续全新父局/合法前缀/对手随机流**。新开发集与最终评估集不同，开发成绩一经使用即进入消费账本。覆盖所有当前训练与预训练血缘，检查规范状态、初态、前缀、增强/派生、完整轨迹和输入重叠；同固定地图标准初态无法独立时，只报“固定初态产品面板”，不称泛化。

建议后续新开发面板采用现有全部 8 个双人地图族各 4 个新父局、每父局两候选座位，共 64 槽/策略；新最终面板至少 80 个父局、160 槽/策略，各自另冻 RNG 及候选评分前的泄漏审计合同。该数量是后续预算设计，**本轮不生成根、不读取未来保密种子、不运行评测**。共享地图结构不构成未见地图泛化；若未来要该主张，另需从未参与训练选择的新几何家族。

推进建议保持：来源主候选相对同状态 H 对照自然胜比例提高 ≥10 个百分点、父局配对 90% 区间下界 >0，跨至少3地图正向，双座位无明显崩溃；最终相对预选强基线提高 ≥10 点且95%下界 >0，对 Heuristic 固定槽自然胜 ≥60%、自然终局率 ≥90%、非法/错误0，浏览器 p95≤100ms/p99≤250ms。均为待正式预注册的门槛，不是已获得棋力。若选更高绝对目标须在训练/评测前确定。

最终交付明确区分：已核实数据资格、未验证标签、训练内拟合、全新开发收益、独立最终证据、固定初态产品成绩、浏览器部署检查。本轮不登记新模型，不部署，不宣布研究目标已实现。
