## 二、本次新发现：原报告不足以支撑几项关键诊断

### 1. 教师学生没有教师验证集；连 H0 验证目标也混用

对 **实际送入 trainer** 的 B0、B1、B1e、B0h_beh 文件分别扫描，四者验证分区的输入序列和目标序列哈希完全一致：

| 验证项 | 实测 |
|---|---:|
| 验证行数 / 不同输入 | 5,316 / 5,316 |
| 来源为 H0 的行 | 5,316 |
| 有 `teacherActionCode` 的行 | **0** |
| 标明 `targetSource=l1` 的旧行 | 546 |
| 未标 targetSource 的新行 | 4,770；构建器将实际行为动作写入 target |
| 实际 target 与 L1 相同 | 4,542/5,316，约 85.44% |
| 实际 target 与行为动作相同 | 5,263/5,316，约 99.00% |

训练侧 B1 的 12,021 行全部是 B100 标签；B1e 的 3,374 行也是 B100 标签。因此：

- B1/B1e 的 val 衡量的是在 H0 状态上对混合 H0/L1 目标的一致率，**不是 B100 保真度**。
- B1e 的 train 81.7% 与 val 29.7% 使用不同策略、不同分布的目标，不能直接相减后认定其教师泛化失败。
- `B1e_best` 是上述 H0 验证指标选出的检查点，不是“教师验证最优”。补测它 0/20，并没有完整排除教师目标下的更佳检查点。
- B0 训练用 L1，但验证中 774 行的实际目标与 L1 不同，`~45% val` 不是一个纯净的 L1 模仿率。
- 粒度诊断另用 `l1ActionCode`，与训练日志 val 的目标又不同，不能直接串成同一条准确率曲线。

这些问题不会推翻已经发生的 0/20、2/20 负结果，但会推翻以这些 val 数字为依据的部分原因解释。

相关代码：`v17/tools/build_v17_dataset.ts`（target 写行为动作）、`make_train_variant_v17.ts`（训练臂换标签）、`make_v17_pool_trainer_input.py`（原样并入 val）、`train_v17.py`（读取 targetActionIndex）。证据：`v17_validation_audit_20260927.json`。

### 2. 干净验证集严重缺少开局，也没有学生自身状态

同一实际验证分区：

- 已完成玩家回合 0–2：**2 行，0.038%**。
- 3–7：953 行，17.93%。
- 8+：**4,361 行，82.04%**。
- 学生与 B100 来源：均为 0 行。

去除重复输入是正确修复，但开局在确定性地图上高度重复，去重后验证覆盖几乎消失。模型即使在招募、出城、指挥官保护上显著变差，汇总 val 也可能变化很小。纯 H0 数据训练更贴合 H0-only val，却更不适应学生犯错后的状态，这足以解释部分“val 更高而实战更差”，不能宣称模仿准确率与棋力普遍反向。

价值验证也有同类限制：606 行、38 个 family，**没有 0–2 阶段**。V0 总 MSE 0.157；3–7 阶段为 0.352，8+ 为 0.037，Mourningstar 为 0.613。它确实在该验证集上胜过常数，但尚未证明开局估值和候选分支排序可用。

### 3. L1 分数与标签有可定位的工程不一致

`v15/tools/labeler_l1_v15.ts` 在同一个 `HeuristicAI(rng)` 上依次调用：

```text
scoreCandidateActions(...)  → 记录 scores，消耗随机数
getAction(...)             → 内部重新 scoreAction，再消耗随机数，产生标签
```

`heuristic_ai.ts` 的各动作评分含随机扰动。因此记录分数和动作来自两次不同的评分，不能要求第一份分数的 argmax 必然是第二次选中的动作。全验证集按 actionCode 对齐后，记录分数 argmax 与 L1 动作一致率仅 **4,475/5,316**。

此外旧 `diag_v17_l1scores_scale.py` 对比的是 `targetActionIndex`，而该字段大多数是行为动作，不是 L1 标签；它得到的 16.3% 不一致混合了两种问题。正确处理是明确分数语义并修复单次评分合同，再决定是否使用软监督。启发式分数仍不能直接称为胜率或真实 Q。

小规模重放：五图各抽20个训练状态，固定诊断seed=2026。100次查询中，原来的两次评分流程有 **4次分数argmax与动作不一致**；恢复到首次评分前的RNG、只执行一次选择后，**100/100与首次分数argmax一致**。这证明双次评分是实际存在的不一致来源；此抽样的4%不等于全数据发生率，也不应替代全验证集计数。脚本：`v17_l1_rng_probe.ts`；结果：`v17_l1_rng_probe_20260927.json`。没有修改现有教师版本、数据或权重。

### 4. “近似平局”“结构不是瓶颈”是过度推断

- B0 在前 1,200 条诊断样本上类型准确率 92%，并不代表攻击谁、移动到哪里具有相同战术后果。该前缀样本也不是全验证集的分层抽样。
- 模型 logits 接近，只说明模型难以区分，不能证明真实行动价值接近。
- 报告的 top1−标签 logit 中位差 0.148 包含 **575 条答对、差值为零**的样本，不能当成错误样本的中位差。
- 训练集日志到 94.8% 说明能记忆这些训练点，不能证明全图关系、寻路、协同决策的表示能力足够。
- 2→4 blocks 无收益，不等于 GAP 或其他全局信息通路无效。四层版本新增残差块也不是保持原模型函数不变的初始化，需测初始化漂移。
- 对五个败局只替换“首次分歧”的一手没有翻盘，仅排除这五次具体干预；它既没证明这些动作等价，也没排除其他关键手或多步纠错。

应保留负结果，收窄解释。单 seed、有限数据范围、反复使用同一 DEV20 的结果，不足以否定整个算法类别。

### 5. 试玩模型与实验冠军不是同一个文件

`src/game/ai/spatial_neural_adapter.ts` 默认从 `src/game/ai/models/` 导入三个内置空间模型；它们的文件 SHA 和解析后的 JSON 均不同于 P1:s2026，且都没有当前冠军声明的 encoderSchemaId。V17 arena 则通过 `--model` 显式加载实验权重。

因此，如果“很差”来自游戏界面试玩，还需记录实际选择的策略、checkpoint SHA、encoderSchemaId、actualPolicy 和回退情况。**当前代码默认没有把 V17 评测冠军自动装入界面。** 本次没有替换这些权重，因为还没有合格的新模型。

## 三、模型为什么差：按证据强弱排序

**已证实：训练目标与最终目标脱节。** B0/B1 等主臂实际使用 CE 硬动作监督，valueWeight=0。它学的是“此处教师按哪个按钮”，没有直接学习哪条行为序列能赢。当前纯模型推理从 action logits 做稳定 argmax，value 虽被返回，却不参与动作选择。V0 只训练 value、冻结 trunk/policy，本来就不会改变下法；其不增胜不能据此否定价值学习。

**已证实：监督没有提供稳定超过对手的改进信号。** 完全复制 H0 在这个对称固定面板上是 10/20；完全复现 B100-Q 是本次记录的 12/20。要达到 18/20，需要生成优于当前策略的可靠行动信息或直接做结果驱动的策略改进。某个不完美模仿者可能偶然超过教师，但单纯提高复制率不是稳定超过教师的机制。

**已证实的数据限制，推定会影响实战：** B0 只有 50 个训练 family；B1e 的 30 局换边示范只有 15 个 family。数千逐步状态不等于数千独立战局。后期占比高、验证缺开局、学生纠错仍来自旧 P1，容易学到局部轨迹特征而不能修复训练后新策略自身产生的错误。

**有源码依据、尚待对照证实的结构风险：** 当前冠军约 5.4 万参数，2 blocks、32 通道，policy 每个候选读取 actor/landing/target 三点特征、53 维语义和20维全局统计，`globalPolicyPool=false`。stem 加四个 3×3 卷积，使每个采样位置的空间感受野最大为 11×11；全局统计和预计算威胁图会提供部分远处信息，所以不能说它“完全看不见远处”，但不存在完整全图空间摘要。现有威胁图用移动力+射程的曼哈顿半径，未按地形阻挡、可达路径和最小射程精确构造；移动语义只有位移距离，缺少目标进展等信息。它必须从稀少轨迹间接学出 H0 显式计算的许多规则关系。

**高度值得验证的闭环问题：** 模型第一次偏离后进入新的状态，教师示范往往没有覆盖；继续在教师自走轨迹上训练仍未消除这一点。B2 只是提高旧冠军状态的占比，不能代表已经测试了“每轮用最新学生重新采集并纠错”的完整 DAgger。该方向的依据是序列决策中状态分布依赖模型自身动作，见 [DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)。

**不能据现有证据下的结论：** “只差更多 GPU/更多 epochs”“网络一定太小”“一改输入必定变强”“B100 无法被任何纯网络蒸馏”。[Policy Distillation 原论文](https://arxiv.org/abs/1511.06295) 给出了成功蒸馏的实例，但这不保证本项目能成功；本项目仍需自己的、标签正确的对照。

### T18-03：让监督携带真实改进信号（P1）
