# V15 实验与评测协议

版本：1.0。数值为本轮预设预算与门槛，**不是已有实测结果**。T15-00 必须将本文件转成含实际 roots、文件 SHA、运行环境的冻结配置；缺这些字段时协议仍为 UNFROZEN。

## 1. 实验身份与问题

| 名称 | 定义 | 用途 |
|---|---|---|
| H0 | 冻结的生产启发式行为实现、每座位 RNG 合同 | 对手与镜像参照，不因修标签器而改 H0 |
| L1 | 相同启发式内核的独立逐状态 RNG 标签器 | 本轮所有基础/纠错数据的共同标签来源 |
| C1 | V14b 历史三 seed 模型 | 历史重评；不直接作为新 schema 正式初始化 |
| C2-s | 新 schema、干净 split、L1 标签训练的基础模型，s 为初始化 seed | 主线共同新基线 |
| D0-s | C2-s final 初始化，只重复旧训练池 | 额外优化预算控制 |
| D1-s | 同一 C2-s final 初始化，旧池 + 新 H0 访问状态 | 新独立数据控制 |
| D2-s | 同一 C2-s final 初始化，旧池 + 冻结学生访问状态，L1 重标 | 学生访问分布纠错 |
| S1 | 按真实回合/联盟展开的新搜索教师 | 条件研究；不阻塞上述主线 |

`D0−C2` 衡量额外训练；`D1−D0` 衡量新教师访问数据替换部分旧曝光的效果；`D2−D1` 衡量在本轮匹配规模/分层下改变访问分布的效果。后两者不能外推为所有数据规模下的普遍因果规律。

### 1.1 禁止同时改变的因素

主线固定网络结构、loss、schema、标签器、过滤规则、优化器与总预算。无依据增加网络层、GAP、value loss、搜索软标签、end_turn 权重或动作裁剪。必要正确性修复统一进入 C2 和三个 D 组。

任何探索性因素另起实验 ID 和配置，不混入主线表格。新 schema 不允许一组重编码、另一组沿用旧输入。

## 2. 数据预算和分区

### 2.1 基础池

优先复用 V14 的可信原始快照/完整轨迹，按新 schema 重编码、按 L1 重标。复用不等于重新生成独立数据。

- 初始来源：原计划 32 train、8 val、8 历史 test roots，先审计实际可恢复数量。
- 正式 C2 目标：最多 6,400 个唯一训练输入、最多 1,600 个干净验证输入；每 root 最多取 220 个状态，并在完整已记录轨迹上分散采样。
- 最低可执行规模：2,000 个唯一训练输入、至少 16 个有效 train 家族；800 个干净 val 输入、至少 8 个有效 val 家族。满足最低规模即可训练，不复制行凑目标数。
- 若去重/恢复后不足，按 T15-00 预排的补充清单采集，最多追加 16 个 train 和 8 个 val roots；仍不足记明缺口，完成可行的标明 PILOT 的小试，不伪称正式三 seed 验收完成。
- 同一标签/特征版本、同一 split，供三个初始化 seed 使用。test 不用于训练、best 选择或超参数调整。

基础采集每 root 上限：12,000 次原子动作、150,000 ms；其他回合上限若启用，记录其真实计数含义。截断轨迹中的精确状态可用于 policy 标签，但终局/value 标签为空。不得因胜负或对模型容易程度筛 root。

旧 test 已参与历史分析，只作为历史诊断集。最终确认来自单独预留的新 root 家族。共享地图是允许的，必须如实限制结论为已测地图/规则。

### 2.2 D1/D2 新池

主实验只采预指定 `subjectSeat` 当前决策的状态：

- D1 该座位由 H0 行动；D2 由冻结的 `C2-42 final@3000` 行动。
- 其他座位均由 H0 行动；教师查询实例与所有行为实例隔离。
- 两组从相同初始 root 清单、相同 subjectSeat 与对手随机流合同出发。分叉后的状态自然不同，不强求动作数相同。
- D1/D2 的同初始家族按配对 cluster 统计，不把两个分支算两条独立初始经验。
- D2 池在三个训练初始化中共用。这是一个固定学生策略产生的纠错池，不得声称是每个 seed 对其自身最新策略反复执行的在线 DAgger。

初始采集计划 16 对 root 分支，2p/3p 各 8 对；最多扩至 32 对。按地图/座位轮换，墙钟/原子步上限与基础采集相同。不得仅取前 N 行。

清理旧池已见输入、val/test 交集及内部重复后，按双方可用的共同分层配额匹配：

1. 分层优先级：人数/地图、subjectSeat、主体已完成回合桶 `0–2 / 3–7 / ≥8`；稀疏时按预登记顺序先合并相邻阶段桶，再合并同人数地图桶。
2. 每层数量取双方可用量的最小值；不足不能靠重复行补“唯一状态”。每 root 对两臂的取样上限相同，单 root 不超过最终 N 的 20%。
3. 目标 `N=1,000` 个唯一新输入/组。若达不到，取共同可实现数量并冻结 N；正式最低 `N≥512` 且双方各至少 8 个有效 root 家族。低于此值只记 PILOT。
4. 新池的目标动作比例只报告，不按 L1 最终标签强制匹配；否则会改变正在研究的访问分布。复杂度/候选数等次级分布同时报告，无法匹配的差异限制结论。
5. 各组每个唯一 key 的循环曝光次数相差不超过 1；具体 sampler 序列先生成并冻结。两组共享状态交集另报，不要求彼此完全不重叠。

历史 D2 下采样到 D1 的规模仅可作低成本诊断；旧采集受查询 RNG 干扰，不能直接充当上述正式新实验。

## 3. 训练配置与确定的消费预算

### 3.1 C2 基线

| 参数 | 预设 |
|---|---|
| 模型 | 现有 spatial-resnet-v2，2 blocks，global policy pool 关闭；其余结构读取并冻结 |
| 初始化 seeds | 42、1337、2026；均从随机初始化训练新 schema |
| 数据顺序 seed | 314159，三个模型相同；split 使用明确 manifest |
| loss | 硬 CE，valueWeight=0，无类别加权 |
| optimizer | AdamW；weightDecay=1e-4 |
| LR | 1e-3 → 1e-5，按真实 optimizer update 的余弦调度 |
| 总更新 | 每 seed 3,000；batch=32，有效曝光恰为 96,000 |
| 验证/保存 | 每 250 更新及 final；额外保留 500、1500、3000 权重 |
| best 选择 | 干净 val top-1 最大；并列时 CE 更小，再并列选更早 update |

按 update 调度为本轮**待实现功能**，不能假设现有 `--lr-schedule cosine` 已满足；现有实现按 epoch 推进。保持旧 CLI 行为可复现，新方式显式配置，例如 `scheduleUnit=update`。

定义：第 `u` 次更新，`u=0..U−1`，使用 `lrMin + (lrMax−lrMin)×(1+cos(πu/(U−1)))/2`。U=1 使用 lrMax。每次更新记录实际 LR，避免 scheduler 调用先后产生一位偏差。

基础池不一定是 32 的倍数，使用冻结的确定性循环 sampler 补齐最后 batch，记录重复曝光；不能静默少算消费。所有计划训练 key 在预算内至少消费一次。

`final@3000` 是比较额外训练和初始化 D 组的共同主端点。best 另报，不能让不同组凭验证择优获得不同隐含训练预算，再将其作为唯一等工作量结论。

### 3.2 D0/D1/D2

同 seed 的三组初始化文件字节 SHA 完全相同，来自对应 C2 final；加载权重后**统一重建 optimizer/scheduler**，以新逻辑运行计 1,500 次额外更新，不复用一组的动量而丢弃另一组的动量。

| 组 | 每次 batch=32 的组成 | 额外更新 | 总曝光 | 旧池曝光 | 新池曝光 |
|---|---|---:|---:|---:|---:|
| D0 | 16 个共同旧池序列 + 16 个旧池控制序列 | 1500 | 48000 | 48000 | 0 |
| D1 | 16 个共同旧池序列 + 16 个 D1 新池序列 | 1500 | 48000 | 24000 | 24000 |
| D2 | 16 个共同旧池序列 + 16 个 D2 新池序列 | 1500 | 48000 | 24000 | 24000 |

共同旧池的前 16 个位置，在三个组相同 update 的 sampleId 必须一致；D0 额外 16 个位置用于控制“新增信息”与“再次看旧信息”。不能声称 D0 与其他组旧池曝光相等。

D1/D2 的 N、分层、总新曝光匹配；每新输入消费频率规则相同。仅拼接不同大小 JSONL 并跑相同 epoch 不满足这份协议。

三个组均使用 LR 1e-4 → 1e-5 的 update 余弦、weightDecay=1e-4、相同 CE 和过滤规则。每 250 更新验证；final@1500 为主比较，best 为辅助。若旧 C2 比较对象使用 best，则必须另外列成非等总训练量分析。

先完成 seed 42 三组，验证消费表与运行链路；实验有效就继续 1337、2026，不能只因结果负面跳过余下 seed。硬契约失败则暂停相应正式实验并修复。

### 3.3 总资源与分阶段停止

- 正式主线：3×3000 + 3×3×1500 = **22,500 次更新、720,000 次有效曝光**。
- tiny-fit：若触发新增诊断，先 8,000 更新、单 seed；仅因具体未拟合问题延至最多 16,000，不自动跑三 seed 阶梯。详见 T15-05。
- 前 100 更新校准速度/内存；输出总预算预计墙钟，不根据准确率修改主预算。
- 非有限数、非法动作、数据身份错配、消费预算不符属于硬失败；保留最小复现后修复。
- 外部资源不足时保存 state/进度，标 BUDGET_EXHAUSTED 与准确恢复命令。epoch 用尽而未达总更新也不能填 3000/1500。

## 4. 真实失败窗口与反事实协议

### 4.1 选择窗口

目标 32 个，允许 20～50 个；来自开发轨迹至少 8 个 root 家族，每 root 最多 4 个。预登记分层和抽样 seed，不只挑 end_turn、教师不同意或最坏败局。保留正确决策对照。

包含审核的 HP=2 结束回合反例、攻击升级边界、移动后攻击/占领、pending 招募处理、support 后再行动、突击后移动、对手即将行动、多方联盟/淘汰边界。某类未出现时用规则夹具补诊断，区分夹具与真实发生频率。

### 4.2 同状态比较

候选集合优先包含模型实选、L1 标签、合法 end_turn、规则 oracle 的即时致胜动作及少量机制相关替代动作。去重后通常最多 8 个；更大合法集仍完整保存，声明反事实只覆盖子集。即时致胜判断只有穷举全部相关合法动作才可声称“没有一步胜利”。

每个比较从同一精确快照开始，用合法 `step` 执行第一个动作，再按相同冻结 continuation 合同继续：

1. 完成本主体本次玩家阶段；
2. 经过实际下个敌方联盟的一个完整玩家阶段，包括其回合开始事件；
3. 到该敌方阶段结束后的第一个真实边界，或更早自然终局。

若中间轮到盟友，真实推进盟友阶段；不能按深度奇偶换符号，不能直接改 currentPlayer。若要用其他边界，必须另列实验，不能混合完整与不完整视野排名。

每分支、每 replicate 最多 256 次真实引擎转换；3 个固定 continuation seeds。查询/叶子内部模拟也计数。每分支额外墙钟上限 30,000 ms，预算未跨到目标边界记 `HORIZON_INCOMPLETE`。32 窗口、8 分支、3 replicate 的计划转换上限为 196,608，不代表实际必须用满。

报告终局、联盟存活、单位死亡/有效 HP、金币、建筑归属、pending 是否解决、实际行动顺序和后续威胁；代理综合分单列其公式，不能替代原始结果。

### 4.3 结论等级

- `PROVEN_LOCAL`：引擎精确一步性质或穷举了声明范围的所有合法回应；明确范围。
- `ROLLOUT_SUPPORTED`：固定延续和采样回应下较好，仅是证据线索。
- `UNKNOWN`：预算不足、分支不可比、方向不稳定或未覆盖关键回应。

将 end_turn 分为“可证明过早”“延迟结束/无效动作”“等价或无已知收益”“未知”。其他合法动作数量、标签频率或一条 rollout 不能决定这些类别。只有已证实且复现于独立窗口的错误才进入下一次定向补样任务；本轮 D0/D1/D2 不临时加入额外类别加权。

## 5. 对局设计

### 5.1 清单、范围与成本

开发面板固定两张已有地图：`SDPLAN:sd-normal:(2) Duel.aem` 与 `SDPLAN:sd-normal:(3) Frozen fields.aem`。每图 4 个预登记新 root seeds，轮换全部候选座位，共 **8 个独立 root blocks、20 个候选座位配对/模型**。

三 C2 + 九 D 模型，共 240 个候选臂。H0 全座位镜像可按同初始 root 缓存，共 8 场实体镜像；每座位从同一 winner/联盟结果重解释。不要把 20 个座位视角误记成 20 场独立镜像，也不要把 12 个模型对同一 root 的结果记成新增独立 root。

每场初始 cap：原子动作 12,000，墙钟 300,000 ms；另有真实玩家阶段上限时先实现计数并固定，不能沿用不明含义的 `maxPlies`。候选已被淘汰但整局未结束时继续主协议，个人淘汰作为辅助结果。

先用与训练/开发/确认不相交的成本校准 roots（每图 2 个）检查自然完成和耗时。若 H0 自身无法高比例完成，依据成本预检统一确定 caps 后再冻结整个面板；不看候选输赢逐场加时。不允许静默加速/修改规则来缩短对局。

上述 248 场按单场 300 秒的串行墙钟上限约 20.7 小时，实际耗时需校准，缓存可减少重复。需要长时间执行时按已冻结的对局 ID 保存进度继续，不能把只跑完便宜地图当作全部完成。

根 seed 由 T15-00 的 master seed、命名空间和序号确定性派生，再检查与所有已用 root 的初始配置/随机流交集。开发、成本预检、数据采集、学生确认、教师确认使用不同清单。只写“不同 seed”而不保留可复现清单不合格。

### 5.2 配对与随机流

对每个初始 root/候选座位：

- 候选臂：该座位用候选，其他座位 H0。
- 镜像臂：所有座位 H0，从该候选座位所属联盟解释结果。
- 对手独立座位流、初始状态、规则和 cap 相同；学生多走几步不应推进其他座位 RNG。
- 缓存键至少含初始状态/map/rules 摘要、引擎/策略依赖摘要、RNG 合同、动作过滤、caps 和运行模式。协议相同但受墙钟负载影响时，报告环境与截断限制。

复用镜像只复用计算，不增加统计独立样本量。无法配对、重复 pairId、身份错配必须报错；不能用 Map 覆盖重复行后悄悄少算对局。

## 6. 统计定义

自然胜/平/负从被测联盟视角记 1 / 0.5 / 0。对局错误不变成负局，截断不变成平局。

对一个臂：自然结果区间为 `[score,score]`；预算截断为 `[0,1]`；错误单独触发错误 gate，报告缺口，不能丢弃后宣称完整计划通过。

一对候选 C 与镜像 H 的差值区间：

```text
lower = C.lower - H.upper
upper = C.upper - H.lower
```

先在每个 root 内等权平均座位，再在每种人数/地图内等权平均 roots，最后按冻结面板权重平均。主开发面板两种人数各占 1/2，避免三人图因多一个座位获得额外权重。自然完整子集点估计和全计划上下界都报告，权重规则相同。

比较 D 与 C2、D2 与 D1 时，直接比较同 root/座位两候选臂的 score/区间；不能仅比较两个各自挑选子集的总体胜率。

必须分别列出：

1. 候选自然完成数 / 计划候选臂数；
2. 镜像实体自然完成数 / 计划镜像实体数，另列按座位展开的完成率；
3. 双臂完整配对数 / 计划配对数；
4. 各类截断、错误、非法动作、fallback；
5. roots、座位视角、训练 seeds、地图的各自样本量。

报告 95% 区间：按初始 root 家族聚类 bootstrap，整块重采样其所有座位/候选/镜像，在地图内分层，固定 bootstrapSeed，10,000 次；训练 seeds 先分别报告，再给等权描述，不能当新增对局 roots。

开发每图仅 4 个 blocks，区间只用于筛选和描述。退化到一个点不表示没有总体不确定性。对截断的全计划上下界不是置信区间：单列上下界；确认时另对每 root 的 lower 值聚类 bootstrap，报告其 2.5% 分位作为保守统计下界。

## 7. 选择与独立确认

### 7.1 固定选择规则

主开发表只比较 final，best 的离线结果作辅助诊断。本轮最多选择一个组/seed 的 final 进入确认，避免对确认集轮番试模型。

进入独立“相对 C2 改善确认”的条件：

- 所有正确性 gate 通过；错误、非法动作、非声明 fallback 为 0；
- 若候选组为 D1/D2，相对 D0 在至少 2/3 初始化上的开发差值点估计为正；若为 D0，则在至少 2/3 初始化上相对 C2 为正。所有组均要求三 seed 平均相对 C2 的全计划差值下界为正；
- 开发候选自然完成及完整配对率均至少 90%；规则关键夹具无已证明退步。

合格组按三 seed 平均相对 C2 全计划下界排序；并列选三 seed 平均干净 val CE 更低的组，再并列按 D0、D1、D2 的固定顺序。组内选择开发表现居中的 seed：相对 C2 的完整配对差值降序、val CE 升序、seed 数值升序排序，取中间一名；该 seed 自身的相对 C2 全计划差值下界也须为正，否则本轮不进入确认。D0 获得资格时，结论是额外优化有益，不能记作新数据或学生分布纠错的收益。

未满足时不消耗学生确认集，输出 `NO_PROMOTION` 或因证据不足 `INCONCLUSIVE`，说明实际已完成的负实验。不得为了触发确认而临时换 best、组合启发式接管或调整筛选阈值。

### 7.2 确认计划

每图预留 16 个新初始 root blocks，全部座位轮换，合计 32 blocks、80 个候选座位。运行冻结候选、对应 seed 的冻结 C2 final、H0 镜像，身份与协议全固定；确认前不能查看这些 roots 的候选结果。

这只是预设起步规模，不保证统计功效。若区间不确定则如实停止并报告，不根据中间胜负选择追加到显著。扩展确认需要另行预登记新批次，旧批次完整保留。

分开裁决：

- **相对 C2 的改善证据**：对应差值的保守 95% 下界 >0，且自然完整点估计支持同向。
- **替换 H0 的候选资格**：相对 H0 同样通过；候选、镜像按座位展开自然完成率与完整配对率均 ≥95%；错误/非法/fallback 为 0；关键规则夹具无已证实退步。
- 只改善 C2、仍弱于 H0：研究有效，`NO_PROMOTION`。

棋力通过还需部署资格：实际浏览器 shared policy 路径、同一权重/schema、端到端延迟与内存、加载、取消/过期状态验证。T15-00 从实际产品约束冻结目标浏览器/硬件和延迟、内存、取消标准；没有明确目标时部署资格为 NOT_MEASURED，不能用测完后的读数倒定通过阈值。Node 速度不能代替浏览器结果。未完成部署资格时只能给研究候选，不能建议直接替换。

仅评测 2p/3p 上述地图不能声称四人或所有联盟模式变强。生产默认保持 H0，本轮不执行替换。
