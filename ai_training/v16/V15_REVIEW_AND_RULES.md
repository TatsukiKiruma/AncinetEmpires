### 2.3 对训练配置的准确回答

| 对象 | 影响与处理 |
|---|---|
| 网络张量维度、权重文件格式 | 仅修开局结算不必改变通道数，旧模型通常仍可加载；运行时继续检查 schema |
| LR、batch、AdamW 等超参 | 不会自动失效，也没有证据要求按加钱比例改 LR；用当前规则数据重新评测、调度 |
| 数据分布、合法候选、教师动作 | 直接改变；首步改变会累积成全局轨迹差异，必须重新生成目标训练/验证数据 |
| 历史快照 | 保留原貌；旧中盘状态不一定非法，但目标分布发生变化，不能冒充新规则普通开局 |
| 已完成训练进度 | 不改写；可用兼容旧权重 warm start 一个新 run，显式新数据/新配置/重置优化器策略 |
| 精确恢复旧 run | 只有数据、batch plan、优化器和环境身份一致时才叫精确恢复；更换数据后是新实验 |
| 旧评测缓存 | 初态和规则身份不一致时失效；不能只按相同 HEAD 或 rulesHash 复用 |
| 历史数据迁移 | 不可给每行金币机械加常数。重新起局生成，或把旧状态明确列为辅助旧域数据 |

优先用 100% 新初态数据建立基线；旧权重可复用。旧样本是否混入以可选的 0%/25% 旧域对照判断，不先默认大比例沿用。

### 2.4 修复实际调用的是整个 startTurnForPlayer

`src/game/apk_skirmish.ts` 默认 `applyInitialTurnStart=true`；`GameEngine` 快照构造默认不重跑。`startTurnForPlayer` 除收入外还处理墓碑衰减、敌军占己方城堡的 50 点伤害、状态衰减/清除、行动重置、地形/能力恢复、中毒及 campaign turn_start。

普通完整血量开局最显著变化是金币；特殊预置状态不能假设只有金币变化。派生残局必须清楚区分“地图初始化”和“恢复已有行动前快照”。已有 `initial_turn_income.test.ts` 两项测试本次执行 2/2 通过；它们不穷尽所有特殊地图脚本。

## 3. 规则如何决定训练重点

以当前普通 SD 默认规则为准，不用其他游戏的胜负定义替代。

| 规则事实与代码位置 | 战略含义 | 必须训练/验证的场景 |
|---|---|---|
| `rule_config.ts`：城镇 50、城堡 100、存活指挥官 50+25×等级，每次己方开始回合收取 | 早占领有复利；指挥官既是战力又是收入来源 | 先占中立经济点、守关键城堡、收入与即时战损交换 |
| `engine.ts:checkWinConditions`：默认无单位且无城堡才淘汰；按存活联盟判胜 | 杀指挥官或占最后城堡本身不必然获胜，必须完成清场/封锁招募 | 有城无兵、无城有兵、指挥官死亡可再招、最后据点收官 |
| `apk_skirmish.ts`：SD 初始配置 300、单位上限 30、等级上限 3；指挥官再招基础 400、成长 100 | 招募受经济、兵种、单位上限、指挥官状态与城堡占位约束 | 首回合新预算下兵种选择、清空城堡出口、保留再招资金 |
| `rules.ts/engine.ts`：pending 招募及 move/attack/wait/end_turn 不是同一个动作 | 一个玩家回合含多个原子动作；错误交出回合可损失整轮机会 | 招募→部署→后续行动、移动→占领、移动→攻击、合法 pending 结束 |
| `engine.ts`：攻击伤害、攻击者经验升级、反击、后续效果有确定执行顺序 | 静态“伤害减反击”可能错过升级后的生存差异 | 升级跨阈值、反击致死、远程最小射程、攻击后移动 |
| `map.ts/rules.ts/abilities.ts`：路径、地形、单位能力共同限制移动/攻击 | 曼哈顿距离不等于真实到达回合；水路、桥口、射程空洞影响交换 | 长距离推进、绕路、水域兵种、卡口保护远程和指挥官 |
| 回合开始有城堡伤害、恢复、中毒、状态衰减、行动重置 | 必须考虑敌人完整回应以及下一己方回合的变化 | 低血安全撤退、占堡后能否活到下回合、延迟恢复/解毒 |
| 治疗、支援、召唤、修复、拆城等有独立条件 | 单一 move/attack 标签不能覆盖所有关键决策 | 用真实合法集覆盖特殊能力，按机会数统计而非强制配动作比例 |

特别注意：一个 `step()` 不等于双方各行动一次；`end_turn` 合法且有时正确。有其他合法动作不构成“过早结束”的充分证据。

### 3.2 伤害、反击和回合边界

`rules.ts` 先用有效攻击加成减去对应物理/魔法防御、地形和能力防御，再按攻击者当前HP/有效最大HP进行整数缩放，最后应用能力倍数；战斗精神是HP缩放的例外。低血不只是“容易死”，通常还会降低输出。

普通反击要求目标活着、相邻且其有效射程覆盖攻击者；反击风暴在距离≤2时有独立能力条件。攻击施加状态以及攻击者升级发生在反击计算之前，所以“先手致盲”“升级后防御提高”和“远程不触发普通反击”会改变交换结果。应走真实引擎预测，不另写一个简化减血公式当标签。

地形防御、恢复与移动费用在 APK 地图上优先读取 APK 地形数据，不能只看地形显示名称。飞行单位不按普通地形防御加成处理。所有路线/地形课程都应调用实际移动和伤害规则。

## 4. 为什么模型依然差：证据与假设分开

### 已证实的训练目标与覆盖问题

- 当前主要优化“复现 H0/L1 的单个动作”。没有可靠机制持续产生比 H0 更好的决策标签。模仿并非理论上绝不能超过教师，但继续只提高模仿率没有可信的 90% 胜率路径。
- 有效 C2 训练 6,140 行：双人 1,348（21.95%）、三人 3,003、四人 1,789；目标五图中的 Liberty Port、Mourningstar 在 train 中为 0，Crossed swords 仅 200。
- C2 train 的 end_turn 70/6,140=1.14%；wait 1,730，move 2,672。稀有动作 top-1 被多数动作淹没，不能靠全量准确率判断回合管理。
- D1/D2 匹配后的每个 1,000 行新池：Duel 73、Icy Paths 123、Frozen fields 424、Midway 380，双人只有 19.6%。这次采样没有朝用户的新五图目标集中。
- 所有有效训练 ledger 的 valueSupervised=0。价值头不能当作已经学会的胜率估计或强教师的可靠叶评估。
- 正式训练 train≈58%、val≈35% 与 tiny-fit100% 同时存在。tiny-fit排除了“完全无法拟合”，没有排除数据覆盖、标签不确定性、完整训练欠拟合和表征不足。

### 结构层面的已知限制，棋力收益仍需实验

当前 2 个 residual blocks 加 stem 共 5 层 3×3 卷积，局部感受野约 11×11。policy 使用动作相关三处局部特征、53 维语义与 20 维全局统计。`global_policy_pool=false` 时，`end_turn` 的三处坐标为空，其自身 logit 没有棋盘位置输入；其他候选的分数仍会影响最终选择，不能说整个最终决策完全不看棋盘。

现有 Python/TS 已支持 GAP 开关。应先做固定数据、固定更新数的 GAP 对照；平均汇聚也不保证解决空间关系，若仍无法区分远方关键状态，再考虑分区池化/显式战略特征等最小扩展。

编码的敌方威胁图是较粗的距离近似，敌方本轮移动标志不一定代表其下一回合可行动范围；同类兵种、等级和状态细节也有信息压缩。需要构造动作最优性不同却编码相同/近似的成对状态，证明缺口后再增加特征。

### 尚未证实，不能直接贴标签的原因

- 具体败局是否由过早 end_turn、错误招募、送指挥官、推进迟缓或收官失败主导：待真实窗口反事实。
- GAP 开启能增加多少胜局、加长训练是否有益、价值学习是否改善搜索：待对照。
- 开局修复对每个模型造成多少胜率变化：本轮未跑旧/新初态的同模型配对因果实验。
