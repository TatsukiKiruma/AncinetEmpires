## 0. 目标、范围与交付规则

本轮回答四个问题：

1. 给模型的棋盘、合法动作、标签与真实引擎是否一致？
2. 在正确数据上，现有网络能否拟合、泛化，并减少真实对局中的关键错误？
3. 学生与启发式的差距中，有多少能由数据修复、训练预算和学生状态纠错缩小？
4. 能否得到经过规则测试与独立对战验证的改进教师，用于后续蒸馏？

必须交付一次通过硬检查后的真实训练及对应对战；若硬检查失败，提交具体反例并先修复，不能用一轮审计报告替代训练。搜索教师失败只关闭依赖该教师的训练实验。

本轮不自动发布权重，不修改游戏规则以方便学习，不覆盖 V12/V13 工件。界面维持现有设计，新增日志和报告使用中文。所有代码注释使用中文。执行者在共享仓库中不得撤回其他 agent 或用户的修改。

新增研究脚本放 `v14/tools/`，配置放 `v14/configs/`，运行产物放 `v14/out/<runId>/`，候选模型放 `v14/models/<runId>/`。修复公共组件时改到公共职责所在模块，避免在新工具里复制另一套引擎或动作解码器。

本文件提议的新脚本和 CLI 均须由对应任务实现；不可把下面的目标文件名当成已经存在的可运行工具。第 10 节单独列出本分支已经存在的命令。

### 0.1 证据与状态

- 每个任务写 `task_status.json`：`NOT_STARTED / RUNNING / DONE / FAILED / BLOCKED / INCONCLUSIVE / BUDGET_EXHAUSTED / DEFERRED`。
- `DONE` 仅表示该任务验收实际完成。文件存在、脚本能导入、包已生成均不等于验收通过。
- 缺失指标写 `null` 并记录原因，不填 0，不把未执行标成通过。
- 结论标注 `MEASURED`（本次实测）、`CODE_CONFIRMED`（源码确认）、`HYPOTHESIS`（需实验）、`HISTORICAL`（引用旧实验）。
- 每个实验保存代码 HEAD、工作区相关源码摘要、命令、环境、配置和输入/输出摘要。HEAD 不能代替未提交源码的身份。
- 主结论必须指向原始记录及统计程序；不能用上轮总结给本轮结论作循环证明。
- 硬错误应立即失败；资源不足标明最后完成的位置、恢复命令和剩余工作，不把资源不足写成方法失效。

## 1. 必须遵守的游戏语义

权威来源：`src/game/engine.ts`、`rules.ts`、`rule_config.ts`、`map.ts`、`abilities.ts`、`env.ts`。测试应通过现有合法动作与 `GameEngine.step`；`unsafeBypassValidationForTests` 不得用于资格结果。

| 规则 | 对采样、搜索和训练的要求 |
|---|---|
| 同一玩家可执行多个原子动作 | `rawActions`、`playerTransitions`、`fullRounds` 分别计数；不能按搜索深度奇偶换价值符号 |
| 移动、行动与突击后移动分离 | 保留 `hasMoved/hasActed/movementRemaining/hasPostAttackMoved`，每一步重新生成合法动作 |
| 招募产生 pending，空城与指挥官堆叠规则不同 | 保留 `pendingUnitId/apkPendingRecruitSource/commanderCastleRecruitUsesPending` 等；处理 pending 不等于再次招募 |
| 支援可重置符合条件的单位行动；治疗有亡灵等特殊规则 | 从能力、等级、状态和规则判断，不能按“友军相邻”概括所有情况 |
| 普通反击与反击风暴受距离、状态和受击后存活影响 | 以真实引擎结果作语义参照，不能把原状态反向伤害当必然反击 |
| 回合开始结算收入、状态、治疗与敌军占城伤害等 | 搜索边界及状态快照必须包含这些事件；不能只改 `currentPlayer` 模拟换回合 |
| 路径受地形消耗、单位阻挡和能力影响 | 曼哈顿圆只能作近似特征，不能作合法移动或真实威胁的裁判 |
| 终局由启用的淘汰条件与联盟决定 | 保存规则指纹；指挥官死亡是否淘汰、最后一兵死亡是否淘汰均由引擎判定 |
| 有效玩家按 `getTurnPlayerIds` 行动 | 排除死亡/禁用玩家，区分盟友与敌人；对三方以上游戏声明对手模型 |
| `winner=null/-1/联盟ID` 含义不同 | null 未结束，-1 规则平局，其余与 root 联盟比较；预算截断没有终局标签 |
| V2 固定最大 20×20 | 超出范围必须明确拒绝或换显式支持的编码；不能静默裁掉棋盘 |

观察值 Observation 是带派生字段的输出格式，不是可直接强转的 GameState。由归档恢复状态时必须执行第 4 节的契约。

## 3. T14-01：重建可信的规则与战术夹具

**依赖**：G0。**主要所有权**：`v14/tools/rule_fixtures.ts`、`rule_oracle.ts`、`rule_suite.test.ts` 及其夹具数据。引擎规则模块默认只读；发现引擎缺陷需单独证明和记录，不在教师里绕过。

现有 `v13/tools/tactical_core.ts`、`tactical_soundness.ts`、`tactical_suite_extended.ts` 的动作类别统计只保留作历史行为描述，不能直接作为新 oracle。

必须完成以下场景。每个场景至少一个应当成立的例子和一个容易误判的反例；除合法性外，测试还要核验动作后的实际结果。

| 场景 | 必测性质与反例 |
|---|---|
| 移动后攻击/占领 | 第一动作不必结束玩家回合；同单位连续动作与其他单位插入的合法性 |
| 普通远程反击 | 本轮投石车距离 3 攻击士兵的样例：反击为 0；近战应反击时确实反击 |
| 最小射程、致盲、反击风暴 | `getEffectiveStats`、受击后状态和特殊反击规则；不能只用动作类型猜结果 |
| 击杀、玩家淘汰与联盟终局 | 攻击最后一兵但未打死；打死但仍有城堡；指挥官阵亡两种淘汰开关；盟友存活 |
| 占领机会 | 即时终局占领；无冲突的必要占领；有紧急威胁时允许先处理别的单位；不要强制所有 capture 首选 |
| 城堡经济与伤害 | 拥有者回合开始的收入/敌军站城堡伤害，比较占领前后跨回合效果 |
| 招募与 pending | 空城招募、指挥官堆叠招募、部署空间被阻挡、pending 时 end_turn 的不同开关 |
| 指挥官重招 | 死亡计数、价格、金币阈值、保留等级经验、允许重招与禁用重招 |
| 支援/治疗/召唤 | 正确的行动者字段、已受支援标记、亡灵治疗、墓碑坐标和生命周期 |
| 突击后移动 | 攻击后仍可专用移动，剩余移动力与原地结束行为 |
| 地形与路径 | 高移动消耗、堵路、飞行/非飞行差异；曼哈顿近不等于能攻击 |
| 多人行动顺序 | 3/4 玩家、下家已死/禁用、下家是盟友、实际下个敌人的两步威胁 |
| 结束回合 | 有必要动作时提早结束造成可证明损失；确实应换回合；反复无效动作的窗口检查 |
| 真平局与截断 | 引擎 `winner=-1`；另一个相同状态由 step/time cap 中断，分类必须不同 |

夹具记录 `stateSnapshot`、规则指纹、root 联盟、合法动作摘要、判定窗口、`acceptableActionCodes` 或结果谓词、oracle 证明方式。

oracle 限制：

- 即时终局用引擎一步结果精确判断；不能把一次启发式 rollout 获胜称为“强制获胜”。
- 复杂战术只有在限制范围内枚举了相关合法回应或有明确结果证明时标 `VERIFIED`；范围外写 `UNKNOWN`。
- 占领延后是否错误，检查在机会窗口关闭前是否完成及后果。无关单位动作可交换时容许多个正确答案。
- “移动了”“攻击了”“治疗了”均不是解围成功证据，要检查威胁对象和结果。
- 夹具要有错误策略反例：过早 end_turn、遗漏确定致胜动作、朝受威胁格移动，oracle 必须能判失败。
- 夹具开发集与最终战术确认集分开；最终集不用于调叶子权重。

交付：`rule_contract.md`、`fixture_manifest.json`、完整状态 JSON、`rule_suite_results.json`、失败反例重放。

验收：所有声明 VERIFIED 的规则谓词通过；未知项不计入通过率；记录未覆盖模式。一个场景在实战轨迹里出现 0 次，不能用 0/0 当资格通过。

## 4. T14-02：统一动作与状态契约，生成干净数据

**依赖**：G0，最终验收依赖 T14-01。**所有权**：新的 `v14/tools/dataset_*.ts`、状态恢复模块、公共动作编解码必要修复。与 T14-03 约定接口，避免双方分别修改编码器。

### 4.1 动作集合必须独立于标签

1. 统一使用 `src/game/env.ts` 中的正式动作编解码或从其提取的公共无副作用模块。覆盖 `Action` 联合的全部 14 个类型。
2. 对同一状态调用一次共同候选构建函数。教师动作不能走特殊解码、补特征或强制保留路径；标签只在候选构建完成后按 actionCode 定位。
3. 先做 `encode(decode(code))===code` 与引擎合法性检查；还要检查坐标、行动者、目标、招募兵种、召唤墓碑等实际字段。正式解码器也须检查输入格式，不能因为“复用了公共函数”跳过验证。
4. 使用全合法的“策略允许集合”：引擎合法集合单独保留；若策略统一禁投降，训练、教师、推理、评测都使用同一明确过滤，记录被过滤的 surrender。不得把未知动作当过滤策略。
5. 对同一个状态随机替换/移除标签，再构建候选；候选码与每个动作的特征摘要必须完全不变。
6. 全候选模式禁止静默跳过。不能解码或无法确认状态时，将整行送入 quarantine，写原因并统计各类型，不得宣称它仍是全候选样本。
7. 如以后研究候选裁剪，独立设实验：选择器不读标签，报告全候选到裁剪候选的覆盖率及按类型召回；当前基线先全候选。

### 4.2 状态恢复与身份

1. 优先保存真实 `engine.getState()` 快照。若使用历史 Observation，编写显式适配器，逐项恢复 status 对象、墓碑 pos、prices、pending、规则覆盖、计数器和脚本状态。
2. Observation 没有的字段不能凭空填默认后声称精确。可从可信地图配置、初始快照和完整动作前缀恢复；仍缺字段则标 `APPROXIMATE`，不能进入需精确搜索/规则标签的数据集。
3. 有原引擎快照时，对比恢复前后全部规则相关状态字段、合法动作集；对代表性动作执行后再比状态和赢家。没有原快照时，归档合法动作相等仅作为较弱证据，不能证明全部未来转移一致。
4. 分开记录 `stateFidelity: EXACT_SNAPSHOT / VERIFIED_REPLAY / OBSERVATION_PARTIAL` 与验证覆盖。本轮正式新数据要求前两者。
5. 超过编码棋盘范围时 fail-fast。对状态重建中不支持的地图/战役模式明确排除并记录数量。
6. 历史终局标签核对联盟、平局、截断；原转换器按 `winner===playerId` 给 ±1 的逻辑不适用于有联盟/真实平局的新数据。

## 5. T14-03：修复规则特征，验证 Python/TS 与动作重排

**依赖**：T14-01/02 接口冻结。**所有权**：`spatial_tensor_encoder` 的版本化扩展、`shared_spatial_policy`、`spatial_conv_net`、Python 对应模型与训练特征接口。与 T14-04/06 约定训练器修改窗口。

### 5.1 特征规则正确性

- 修复反击估计：以真实引擎一步执行作 oracle；分别核对直接伤害、反击、状态、经验/升级与动作后附带效果。最终 HP 差不能不加区分地全部叫“反击伤害”。
- 可采用共享战斗解析函数、合法的轻量模拟或经过测试的预测实现；避免给每个动作独立构建整套昂贵引擎造成在线速度退化。测量真实成本后决定。
- 地形、身份、pending 与状态特征用真实恢复状态计算。覆盖治疗/支援/招募等非攻击类型，确保标签与非标签特征同源。
- 列出尚为近似的通道，例如曼哈顿威胁。若保留，改成准确的描述，不将它用于规则 oracle。
- 做“状态成对”审查：敌人归属与下次行动顺序、城堡 pending 来源、已行动/可突击后移动、支援资格、兵种/能力等变化，能否导致合法/最优决策改变而策略输入不变。
- 只有发现与目标相关的状态别名，才加最小必要特征；同状态不同候选不碰撞不能代替这个检查。策略需要可区分的观测，不要求把无关元数据全部输入。
- 新语义必须有 `encoderSchemaId`/检查点输入 schema。即使张量维度不变，也不允许旧权重静默加载新语义。保留历史 V2 运行路径用于重测旧模型。

### 5.2 真正的一致性与重排测试

从同一份已知正确状态生成同一候选列表，比较 Python 和 TS：空间输入、全局输入、候选输入、逐 actionCode logits、value、最终 actionCode。

- 覆盖所有动作类型、0/1/大量候选、地图边缘、null 坐标、pending、并列最高分、非默认规则；空候选应有明确定义，不能凭空落非法 end_turn。
- 至少 128 个诊断状态，并包含真实样本及规则夹具；维度和有限数值检查必须通过。
- 建议预登记容差：输入最大绝对差 ≤1e-6；FP32 跨语言输出 `atol=1e-4, rtol=1e-4`。超过则定位后解释；不得看结果后任意放宽。
- 当最高分差大于两倍实测数值误差界时，actionCode 必须一致；近似并列单列，使用共同、与标签无关的 tie-break 契约。
- 对固定状态反序与至少 3 次固定种子乱序，目标和辅助标签同步映射；对齐后的 logits、loss、梯度、一轮优化更新满足预登记容差。
- Python float32 梯度/更新建议 `atol=1e-5, rtol=1e-4`，记录绝对及相对误差。关注误差是否随候选顺序系统变化。

交付：`feature_semantics_report.json`、`state_aliasing_cases.json`、`python_ts_forward_parity.json`、`candidate_permutation_invariance.json`、`schema_compatibility.json`。

验收：本轮受控反击反例修复；所有新 schema 的输入/输出验证通过；模型加载时拒绝不匹配 schema。原有模型能按旧路径读取。随后 G1 才可通过。

## 6. T14-04：128 状态可拟合性与训练链路诊断

**依赖**：G1。**所有权**：`v14/tools/tiny_fit.py` 与训练器必要诊断；不与 T14-03 同时修改相同训练函数。

1. 选择至少 128 个干净、不同且可追溯的状态，使用完整策略允许候选和固定教师标签。覆盖重要动作类型和阶段，剔除/单列已证明无法由输入区分的冲突目标。
2. 这是训练集记忆能力诊断，明确标 `diagnostic=true`；不宣称泛化。不得把同一数据的训练成绩当验证准确率。
3. 先使用现有 32 通道、2 残差块结构、CE、`value_weight=0`，关闭会妨碍记忆的额外正则化并记录设置；不要先更换大网络。
4. 预登记初始预算：batch 16、最多 2,000 次总更新、至少每 50 次更新记录完整诊断集评估。建议 lr 1e-3；若失败，仅按预定的 3e-4 对照定位，不无限试参。
5. 训练后以固定 final checkpoint 重新评估全部 128 状态，而不是累加训练过程中各批的混合版本预测。
6. 验收参考：训练目标 top-1 ≥99%（128 状态至少 127 个）。存在经过 oracle 证明的多解时同时报告 exact 与 acceptable-set；不能凭相同代理分数把动作并成“等价”。
7. 检查梯度、参数变化、loss 下降、目标索引、数据加载、候选 padding 与 mask。当前 `equiv` 分支是 CE 加 group loss，不能自动当成去掉唯一标签要求的纯等价目标。
8. 若仍不能拟合，按层定位输入别名、标签噪声、梯度与优化问题；只扩大诊断预算并给出理由，不启动大池训练。未到目标写 FAILED/INCONCLUSIVE/BUDGET_EXHAUSTED，对应不同原因。

交付：`tiny_fixture_manifest.json`、`tiny_fit_metrics.json`、学习曲线、检查点、逐状态错误清单、实际消费记录、TS 导出模型复验。

G2 通过条件：可拟合性成立、导出后仍达标、标签和数据摘要与声明一致。不能用旧 2,560 状态约 38% 训练准确率替代本项。

## 7. T14-05：修复评测统计，冻结开发与确认协议

**依赖**：G0，规则自测依赖 T14-01。**所有权**：`v14/tools/eval_*.ts`、结果聚合与恢复工具。可以复用 V13 纯分类函数，不能直接复制旧汇总数字。

### 7.1 对局身份与终止

- 候选在某座位、其他座位为固定版本启发式；镜像为全启发式。枚举引擎实际有效座位，并按联盟视角统计。
- 每个 `(初始状态摘要, 规则摘要, 场景, seed, 对手版本, 预算)` 只运行一个镜像，多个座位引用它。缓存键必须包括所有会影响结果的配置。
- 记录真实 `actualPolicyId/checkpointSha256/encoderSchemaId`；静默回退禁止，任何回退单列。人机界面的允许回退策略不能混入纯模型强度成绩。
- 赢家、真平局、步骤上限、玩家回合上限、时间上限、取消、策略错误、引擎错误互斥分类。V13 的 `undecided=total-natural` 会包含 errors，新的两个计数不能重叠。
- 候选玩家先被淘汰而整局尚未结束时：FFA 可以记录不可逆淘汰作为辅助结局，但不要伪造整局 winner；主协议继续到自然终局或截断。联盟中队友仍能获胜时更不能按个人淘汰算联盟失败。
- 时间预算在动作调用外层有可取消执行保护；同步长调用内检查时间不等于可硬中断。超时记录实耗与超预算，不把迟到动作应用到已变化状态。
- 不允许通过缩短步骤上限、改判平局或删掉慢局提高名义胜率。

### 7.2 统计定义

自然终局得分 `s=1`（赢）、`0.5`（规则平局）、`0`（输）。同一座位的配对差值为 `d=s_candidate-s_mirror_view`。

1. 两边均自然结束才进入完整配对点估计；只报候选自然结束子集胜率不能代表全部计划对局。
2. 预算截断一侧的未知最终分数用区间 `[0,1]` 做上下界；差值区间为 `[C_low-M_high, C_high-M_low]`。这是不确定性界，不是把截断改判胜/负。
3. 错误不是正常截断；报告错误率并判该实验有效性不通过，不靠上下界掩盖策略崩溃。
4. 按 `(场景, 初始状态/seed/root)` 聚类：同 root 的全部座位、共享镜像、模型重复测量一起抽样。不能把 3 座位×10 seeds 当成 30 个独立镜像。
5. 先按各 root 的全部预定座位平均，再按地图/模式预定权重聚合，避免多人地图或长局多行取得额外权重。报告每地图、座位、人数和规则配置的分层结果。
6. 给出聚类 95% 区间、自然完成率、错误/截断分布和原始 W/D/L。固定地图面板的区间只支持该面板；地图泛化另用未见地图组。
7. 用固定大小确认集一次性评价冻结候选。若结果不确定，报告 INCONCLUSIVE；追加样本需要新预登记批次，不能看显著性随意停止。

### 7.3 建议起步规模与资源校准

以下是执行默认值，不是统计充分性的定理。T14-00 可在实际机器校准后调整一次并说明原因，随后同一实验各组共同执行。

| 层级 | 规模与用途 |
|---|---|
| 协议自测 | 同策略同输入至少覆盖 2p、3p、联盟/禁用玩家夹具；trajectory/action digest 一致；故障注入正确分类 |
| 成本预检 | 每种人数/地图候选各 1 个镜像和短试跑；只看能否运行、延迟和资源，不据候选成绩筛图 |
| 开发强度 | 至少 1 张 2p + 1 张 3p 地图，各 4 个开发 seeds，全座位；基线三个模型 seed 都测；方向性结果 |
| 冻结确认 | 至少 3 张地图、每图 10 个新 seeds，即 30 个独立场景-seed blocks，全座位；只测预先冻结的一个候选/配置 |
| 泛化声明 | 至少一个不参与训练和调参的地图/规则子面板；四人模式须有单独四人实测，不能由三人外推 |

`Duel`、`Midway` 可作为已有场景入口，但不要把它们当足以代表整个游戏。Crossroads 历史成本很高；如果不纳入当前资源预算，范围声明中明确“四人整局资格未完成”，仍必须完成四人规则夹具。

默认对局 step cap 可从 20,000 开始，wall cap 由成本预检冻结；时间保障应在整个评测执行周期可恢复。预算不能按候选修改。候选与镜像都保存 action trace、周期性状态快照、规则和棋盘摘要、逐决策耗时。

交付：`eval_protocol_v14.json`、`eval_selftest.json`、故障注入结果、`arena_manifest.json`、可恢复 games JSONL、聚合程序和误差界自测。

验收：自测的轨迹一致性成立；胜者为联盟、平局、错误、截断、镜像去重和区间计算通过人工可算的小例子。旧模型可以读入重测，不强制重跑整个历史矩阵。

## 8. T14-06：完成干净的明确教师基础训练

**依赖**：G1、G2、T14-05。**所有权**：`v14/tools/collect_baseline.*`、`train_baseline.*`、configs、训练及数据产物；共享训练器的改动由 T14-03/04 负责人合并后再用。

### 8.1 数据采集与采样

### 8.3 训练配置与学习判断

- C1 三个 `modelSeed=42/1337/2026`；split manifest 固定，`dataOrderSeed` 在各架构/数据变体之间固定，例如 314159。若研究数据顺序随机性，单独设实验。

验收：三 seed 的真实训练和对战完成；结果可解释即可完成任务，不要求虚构正收益。G3 不等于战胜启发式。

## 9. T14-07：按回合与联盟语义改造、验证搜索教师

**依赖**：T14-01/02、T14-05；可与 T14-03/04/06 并行研究。**所有权**：`v14/tools/teacher_*`、必要的公共规划/教师模块。对 `heuristic_ai.ts` 的线上默认行为变更须独立记录；推荐保留 H0 并新建显式教师配置。

先复用和审查 `src/game/ai/planning.ts`、`tools/v10_turn_aware_search.ts` 的现有规划/宏动作/转换计数能力。不要仅根据其注释宣称已支持，也不要重复实现一套未经测试的回合引擎。

### 9.1 先明确现有教师的真实缺陷

1. 静态叶子本身是确定性的；候选预排序/rollout 内有状态 RNG 是另一层。分开做固定状态和动作下的重排、重复、线程/批次一致性测试。
2. 检查原子动作截断与正常换回合的比例：有多少候选实际看到敌人回应，有多少仅看己方继续走。对所有动作按真实预算完整记录。
3. 检查叶子中的兵力 `hp/100`、多人 commander 覆写、存钱/招募资产换算、路径/威胁近似；用规则夹具测每项偏差，不先认定唯一根因。
4. 大接管阈值、零阈值、更多候选是不同因素；做同状态、同候选及同总引擎转换预算的对照。

### 9.2 新教师设计约束

- 教师策略与标签工具调用同一个内核。候选按稳定 actionCode 标识，禁止按数组下标派生动作随机 seed。
- 最简单可复现版本使用确定性 tie-break/rollout；保留随机探索时，以 `stateHash/actionCode/replicate/kernelVersion` 派生独立流，并记录每个 replicate。一个动作的评分不得依赖此前评了哪些动作。
- 以真实引擎逐步构建 move→attack/capture、recruit→pending 处理、support→再行动、attack→post_attack_move 等必要短链；任何返回给游戏的动作仍只是当前第一步，后续重新规划。
- 同一玩家的多动作阶段不会自动变成敌方回合。显式处理 end_turn；下一玩家由引擎选择，不能直接篡改 currentPlayer 来省略收入/状态/伤害。
- 搜索目标是跨过有意义的事件边界并看到实际对手回应。预算不足时记录 `horizonIncomplete`、触及玩家/回合、未评分动作和覆盖率，不能把它与完整视野的高置信标签混用。
- 深度不同的候选比较要声明公共规则：固定玩家阶段窗口或同一边界的完成情况；诊断混合视野偏差。不能把提前截断恰好分高解释成找到好棋。
- 2 阵营可研究根联盟 maximin。3+ 阵营必须声明是 actor 自利启发式 rollout、MaxN 或保守 paranoid 近似；不得把所有敌人默认为一个真实协同阵营，并声称精确最优。
- 终局以联盟判断；非终局启发式不会等同终局证明。一次 rollout 胜利命名 `rolloutTerminalWin`；只有覆盖所宣称回应范围的证明才命名 forced win。
- 叶子需要正确反映规则终局、资源、建筑/招募机会、有效 HP、真实可达威胁和行动时序。权重从开发夹具调试，最终资格不用同一批夹具。

### 9.3 预算与资格分层

离线标签先按总引擎转换预算试 `64/256/1024`，候选生成、己方 rollout、敌方回应及叶子内模拟全部计数；另计合法动作生成次数、评分次数、clone 次数和墙钟。节点数有限不等于时间硬上限。

离线教师可较慢，调度器必须能取消、恢复并对慢样本写截断原因；若研究在线教师，使用 worker/watchdog 验证端到端预算，包括 fallback 计算。教师线上是否 1 秒内返回不作为离线蒸馏的必需条件。

| 资格 | 必须证明 | 允许用途 |
|---|---|---|
| T-legal | 输出合法、状态无污染、动作码与评分对齐 | 源码与局面诊断 |
| T-label | 可复现、标签预算完整、已验证战术集无已知关键退步 | 小规模蒸馏探索，不能宣称强教师 |
| T-strong（GT） | 独立开发对战显示相对 H0 的正向配对改善，并在冻结的教师确认集获得支持；关键已证明战术无回退 | 以“改善教师”为前提的蒸馏主实验 |
| T-online | 另通过目标硬件上的取消/过期状态/端到端延迟资格 | 在线搜索试运行 |

T-strong 的对战区间、完成率与错误门槛采用 T14-09 同类标准，教师确认集与最终学生确认集分开。因预算只能完成开发小样本时标 PROVISIONAL/T-label，不升级 GT。

比较 H0、默认 BattleSearchAI、改造教师。报告实际不同动作率、已验证战术收益、真实对战和成本。不同动作率本身不是改进；同一代理 Q 增大也不是独立质量证据。

交付：`teacher_kernel_contract.json`、`teacher_invariance.json`、`search_depth_coverage.json`、`teacher_budget_profile.json`、`teacher_qualification.json`、完整错误重放。

停止条件：非法/不可复现/关键规则测试失败时停止产生正式标签；GT 未通过则禁止声称“蒸馏更强教师”，但启发式纠错实验继续。

## 11. T14-08：学生访问状态上的纠错与条件蒸馏

**依赖**：T14-06。**所有权**：`v14/tools/dagger_*`、`distill_*`、数据 lineage 与训练配置。搜索蒸馏分支另依赖相应教师资格。

### 11.1 启发式纠错分支（GT 不通过也可执行）

目的：缩小学生在自己访问状态上的误差，验证固定教师轨迹的分布差异。标签教师可以是明确版本的启发式，不需要预先强于它自己。

固定一个预登记学生初始化检查点及每 seed 对应初始化，在开发 root 中运行学生轨迹；收集实际遇到的状态，离线调用同一教师内核标注。`behaviorPolicyId` 与 `labelTeacherId` 分开保存。

最低首轮规模建议 8～16 个新训练 root、512～2,048 个决策点，按 root/阶段/关键规则均衡；不是取前 2,048 行。所有分支归到母 root，不能移入验证/测试。若轨迹由行为混合策略生成，保存混合概率与实际每步行为来源。

对照必须使用相同初始化、同一旧池、同一新数据数量、同样更新数与数据顺序策略：

| 组别 | 数据 | 解决的混淆 |
|---|---|---|
| D0 replay | 仅旧数据再训练 | 改善是否只是更多更新 |
| D1 fresh-offline | 新采教师访问状态 + 旧池 | 改善是否只是新增独立数据 |
| D2 student-states | 学生访问状态由教师重标 + 旧池 | 学生状态纠错的额外价值 |

默认每组额外 1,500 更新，旧/新样本混合比例固定，例如 1:1；D0 用重采样匹配曝光量。至少两轮前，先以三个模型 seed 完成首轮受控比较，防止无约束不断堆数据。

每组保存实际 unique new samples/roots optimized。仅把数据写入 JSONL 不算 DAgger 完成。对战使用同一开发协议，报告相对 C1 与 H0 的差值。

### 11.2 搜索标签分支

- T-label 只允许标为探索性小试；GT 通过后才进入“更强教师蒸馏”主实验。
- 全候选必须仍在学生输入中。搜索只评了一部分动作时，用独立的 `teacherScoreMask`/pair labels；禁止把未评动作补成 0 或最差分，并对全候选 softmax 称为完整教师分布。
- 优先蒸馏有一致视野、可复核差异的排序或多解标签。每条标签保留 root-state、动作码、rollout 证据、评分类型和置信/截断字段。
- 不把 proxy Q 填成真实胜率或自然终局 valueTarget。软目标温度需按训练集尺度标定，再冻结，不能查看测试标签调温度。
- 现有 `loss_mode=soft/equiv` 仍附加 CE，新增纯组目标/掩码目标时写清公式、兼容性和真实反例测试；标签噪声不能靠一个名称消失。
- 比较相同数据上的 CE、经过验证的排序/组目标；同更新、同初始化、同 split。蒸馏成本另列，不能仅报学生推理快而忽略标签成本。

交付：三组配置、纠错样本清单、label audit、训练消费与离线/对战结果、学生状态失败分布、`dagger_decision.json`。

验收：可以识别更多训练、新独立数据、学生状态纠错各自贡献。GT 失败时输出搜索分支 DEFERRED/FAILED，但不自动把 D0/D1/D2 标 BLOCKED。

## 12. T14-09：冻结候选与独立强度确认

**依赖**：T14-05/06；若选择纠错/蒸馏候选，则相应 T14-08 完成。**所有权**：协调者与评测负责人。不得由训练负责人反复看确认结果挑新 checkpoint。

1. 根据开发阶段预登记规则选择一个检查点与推理配置，冻结 SHA、输入 schema、对手版本、地图/规则和 budgets。候选为网络单独执行还是启发式+网络组合必须明确。
2. 在未参与训练、调参、选择的确认集上运行 T14-05 协议。其他模型 seed 用于开发稳定性描述；确认的是这个明确候选，不夸大为整个训练方法必然有效。
3. 主指标为按独立 root 聚类的配对自然得分改善；同时报告全计划对局不确定性界与逐地图/座位结果。
4. 建议通过标准：策略/引擎错误为 0；规则关键夹具无已证明退步；自然完成率 ≥95%；冻结确认的配对改善 95% 区间下界 >0，且在截断敏感性分析下结论仍成立。后者不能只把困难超时局丢掉。
5. 若未达到较高完成率或完整配对数不足，结果为 INCONCLUSIVE；可提出新的固定预算确认批次。阈值是本轮发布证据门槛，不是对棋力的数学保证。
6. 报告真实端到端延迟 p50/p95/p99/max、模型加载时间、内存、fallback、非法动作、worker 取消和过期状态处理。若拟供网页实际运行，必须在浏览器运行相同加载身份和代表性局面，Node 耗时不能替代浏览器结果。
7. 如果只有部分人数/规则通过，只为那个范围声明资格。四人未评测不能写“全模式更强”。

发布建议单独给 `PROMOTION_CANDIDATE / NO_PROMOTION / INCONCLUSIVE`，并列出依据。用户当前授权是训练与评估任务书；本轮执行任务完成后由用户选择是否替换生产默认。

交付：`frozen_candidate.json`、确认对局与全部重放、`confirmation_report.md`、`runtime_identity_and_latency.json`、`promotion_decision.json`。

## 13. T14-10：价值头探索（条件任务）

**不阻塞基础训练、启发式纠错和交付。** 不按“自然终局数达到某个常数”自动启动或通过。

启动条件：自然终局标签与联盟语义正确；数据有跨 root、地图、座位、规则与胜负的有效覆盖；有独立 held-out 校准集；训练/验证 lineage 隔离。30 个自然 roots 可做诊断，无法单凭这个数字判定任何价值方法不可能。

1. 终局标签 +1/0/-1 按 root 联盟处理；截断缺失值设 mask。逐局回报相同是正常监督形式，不用“局内熵为 0”判定不可学。
2. 明确学的是哪个行为/后续策略下的结果。混合策略记录 policy/version；不能把所有历史轨迹当成同一种最优价值。
3. 以 root 或 trajectory 权重防止长局主导；比较常量、座位/地图先验和简单状态基线。
4. 输出独立集 MSE；若映射到概率，明确平局口径并给 Brier/校准曲线与分层结果。预测分数相关性不能自动当胜率校准。
5. 只有离线价值优于简单基线后，再用固定搜索预算测试接入价值头是否改善实际决策/对战，不能直接发布。

交付：`value_dataset_audit.json`、`value_baselines.json`、`value_calibration.json`、等搜索预算消融或未启动原因。

## 16. 防止重复旧错误的硬约束

- 不用“教师标签在下标 0”直接推出位置作弊；先测候选等变性和目标映射。
- 不把漏掉非标签招募/治疗行动者等标签相关输入错误解释成神经网络能力不够。
- 不把相同编码器对同一近似重建状态输出相等，称作真实状态及 Python/TS 前向全通过。
- 不把存在合法 capture、执行任意 move、攻击最后一兵等动作类别当战术成功证明。
- 不把规则默认值当所有地图实际规则；不把玩家 ID 当联盟 ID。
- 不把静态叶子确定性、rollout 随机性和实际棋力混在一个结论里。
- 不把离线教师算得慢直接判为不能蒸馏；在线耗时资格另测。
- 不把 8 epochs 的上升学习曲线当模型容量上限，不把 37 roots 的几万行当几万局。
- 不把教师不强于启发式当作停止基础模仿/启发式 DAgger 的理由；也不承诺模仿会自动超越教师。
- 不把未知搜索分数补 0、截断填负标签、错误当平局、共享镜像当独立对局。
- 不为宣布提升而改变游戏规则、延长/缩短某一组独享预算或挑选有利地图。
- 不让“重新审计”成为最终产物：硬检查通过后，真实训练、消费核验和对应对战必须落地。=
