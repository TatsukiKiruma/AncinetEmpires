## 2. 可以接受的进展，以及适用范围

### 2.1 网络可以拟合这个小样本任务

三个 final 检查点的 128/128 在 TS 上可以重现，说明当前结构至少能解决这组诊断任务。无需再以“网络完全学不会”为出发点继续堆 tiny-fit 试验。

但实际进入优化的是 **127 个样本，另 1 个是验证占位**。三个 seed 都是 16,000 次更新、254,000 次曝光；“128 状态全部被优化”的脚本说明与实际 split 不一致。准确说法是：127 个训练状态及一个占位验证状态，最终共 128 个评估状态全部答对。

这不推翻小样本可拟合的证据，但应修正台账。若要严格完成原任务的“128 个训练状态”验收，增加明确的 train-only 诊断模式或独立验证占位，不再依赖含糊的 train/val 说明。

### 2.2 策略网络前向对齐取得了可信结果

加载器维度修复有实际作用，48 案例的策略 logits 与 trunk 对齐本次也得到相同读数。它支持“策略前向没有发现跨语言数值差异”。

原任务还要求 value 数值、受控并列动作、完整梯度/更新重排等覆盖；其中 value 和 tie-break 被原报告明确列为未测，不能把 T14-03 所有要求概括成全部完成。当前 policy-only 基线的主要结论不依赖未使用的 value 输出。

### 2.3 基础模型仍明显弱于本次对手

三 seed 的 best val 分别为 38.00%、38.31%、38.06%；最后 epoch 的 train 指标约 68%～71%，val 约 36%～38%，验证 CE 相对中期上升。

这是训练集表现继续提高、验证集改善停滞的证据。后续重点应转向有效独立数据、状态分布和关键错误，而不是把 tiny-fit 的“去正则、延长更新”原样搬到正式训练。训练集尚未 100% 与泛化过拟合可以同时存在；当前日志没有证明正式模型继续加更新就会更强。

**NO_PROMOTION 合理，不建议替换当前默认策略。** 这是审核判断，不需要把没有优势的模型交给用户承担选择风险。

## 3. 需要纠正的主要问题

### [P1] 教师“同种子不可复现”探针实际换了种子，也换了局面

位置：`v14/tools/teacher_qualification_probe.ts`。

原探针在每次 replicate 使用：

```typescript
streamFor(seed + replicate * 7919, replay.ally)
```

因此它测的是不同随机种子下的策略差异，不能用于否定同种子可复现性。不同 seed 给出不同动作是有随机 tie-break 的策略可能出现的正常行为。

更严重的是，重建 failure window 时把候选座位也交给启发式走，然后用相同 step 数冒充学生窗口。策略一旦分叉，step 相同不意味着 state 相同。

本次实测：

- 正确使用学生检查点重放前 40 个窗口，**40/40 实选动作与窗口记录一致**。
- 原探针使用的全启发式重放，与学生轨迹有 **37/40 个状态不一致**。
- 对其声称不可复现的第 37 步，全启发式状态用相同 seed 重新初始化三次，动作均为 `move:u_7:3,8`。
- 按原探针更换 seed，才得到报告中的 `move:u_7:3,8 / move:u_7:4,9 / move:u_7:3,8`。
- 正确学生局面的同种子教师动作则三次都是 `attack:u_8:apk_u0`。

所以 T-label 的失败理由应改成 **INVALID_PROBE / 待重测**，而不是“发现 RNG bug”。T-legal 的有限结果只适用于它实际构造的启发式状态，不是声称的学生窗口。它测试的是 HeuristicAI，也没有完成搜索教师的回合/预算/强度资格。

修复要求：使用已保存完整快照或原 action trace 重放，验证 stateHash/当前玩家/合法动作摘要；同 seed 复现与跨 seed 多样性分开；玩家视角使用 `getAllianceId`，不把 player ID 当联盟 ID。

标签仍需要清晰的 RNG 合同：可按完整 RNG 状态复现历史教师，或为新版本标签器提供固定的逐状态/动作 seed。此修改应限定在新教师/标签器版本中，不能为了通过错误探针而改变 H0 对手的生产策略。

### [P1] “提前结束回合”尚未被证明是错误

位置：`v14/tools/failure_attribution.ts`、原报告第 4/8 节。

当前判定只是“存在非 end_turn 合法动作却选 end_turn”。游戏没有要求必须执行全部可选动作，这个布尔值只能是诊断提示。

本次重放第 114 步：

```text
回合 6，玩家 0，金币 100
仍能行动的单位 u_10：士兵，HP=2，未移动、未行动
合法动作：
  move:u_10:3,7
  move:u_10:2,6
  attack:u_10:u_6
  attack:u_10:u_11
  wait:u_10
  end_turn
```

其余三个己方单位已经行动。原报告“该处可招募单位固定”的解释与真实动作集不符；没有招募动作。2 HP 单位的攻击可能收益很小或遭反击，移动是否值得做需要真实后续评估；本次没有证明 end_turn 最优，也没有证明它劣于其他选择。

`end_turn` 在原子动作数据里占 1.2%，本身不证明欠采样。每个玩家回合可以包含多次移动、攻击、招募等动作，结束动作天然较少。更不能从“可能过早结束”推导出“应该提高结束回合标签比例”：干预方向需要先明确。

应先比较这些替代动作到本方回合结束及敌方回应之后的后果，并区分过早结束、过晚结束、等价等待、必要行动被遗漏。按确定错误补样本，而不是按动作稀有程度直接加权。

“237 个窗口没有错过一步胜利”也只排除了一个非常窄的错误类别，不代表没有战术错误，更不能定位整局失败的主因。

### [P1] G1 仍有反击预测和历史 schema 的真实反例

位置：`src/game/rules.ts::estimateCounterDamage`、`src/game/ai/shared_spatial_policy.ts`、`spatial_tensor_encoder.ts`。

**反击投影漏算本次攻击带来的升级。** 引擎在反击之前执行 `addExp`，升级会改变攻击者防御；投影只扣目标 HP、附状态，没有对攻击者应用该经验步骤。

本次合法受控样例：相邻的两个 0 级士兵、满血、道路地形、level cap 3。

| 攻击前经验 | 攻击后等级/经验 | 特征预测反击 | 引擎实际反击 |
|---:|---|---:|---:|
| 0 | 0 / 30 | 25 | 25 |
| 90 | 1 / 120 | **25** | **22** |

已有 145 条规则断言通过，但没有覆盖这个反例，因此不能据其宣称全部战斗语义已经对齐。修复要保持引擎规则不变，在预测中共享完整结算顺序，增加跨升级阈值的正反例。

**旧 V13 schema 实际仍收到新语义。** shared policy 按权重选择了 24/26 通道，但候选编码只接收 `v1/v2`，统一使用新版反击预测。加载历史 `spatial_resnet_v2_checkpoint.json` 走真实 shared policy 路径，在投石车距离 3 攻击士兵的例子中：

```text
权重解释的 schema：spatial24_global20_actionSemantics32_v13
旧 V13 反击特征：50
当前实际送入该权重的反击特征：0
```

模型仍能加载不等于输入语义兼容。这会影响历史模型对照和手动选择旧模型的运行行为；它不是当前 26/53 C1 弱的直接证据，但违反了旧 schema 保持可解释的契约。

修复要求：状态及动作编码都由显式 schema 分派，或明确拒绝不支持的历史推理路径。不能只靠维度匹配。修正当前新特征后要重建相应数据并记录新 schema/数据摘要。

### [P1] D0/D1/D2 对照仍不具备因果解释力

原报告诚实标 INCONCLUSIVE 是正确的，但缺少几项需要一并处理的混淆：

| 项目 | D0 | D1 | D2 |
|---|---:|---:|---:|
| 实际额外更新 | **1,000** | 1,500 | 1,500 |
| 唯一新增状态 | 0 | **1,070** | **4,787** |

D2/D1 的唯一新增状态比为 **4.47 倍**；如果用“多出多少”口径则是多出约 3.47 倍。报告应明确比例，避免“差 3.5 倍”歧义。更重要的是 D0 连额外更新数都未匹配，无法排除增加训练量的收益。

另有代码问题：`collect_student_states.ts` 在对手行动时先用 `seatAi` 选择实际动作，随后又用**同一个实例**做教师重标。第二次查询推进其 RNG，会改变以后的对手动作流。是否请求标签不应改变行为策略。脚本还采集全部当前玩家的状态，须分别记录主体学生、其他座位及混合比例，不能全部混称学生决策。

重做时需要独立标签 RNG/教师实例；有无标签查询的行为轨迹应相同。三组匹配额外更新、初始化、旧/新曝光、地图/座位/阶段分层，并对 D1/D2 匹配唯一新状态规模。先将 D2 分层抽到 D1 的规模可作低成本试验，扩容实验另列。

### [P1] 跨分区重复没有修复，G1 不能无保留 PASS

执行者发现 150 个跨分区重复任务组，有价值；但仍沿用原验证集选 best，然后继续把任务列为 DONE。

去重统计脚本使用的 `sample_key` 包含目标动作与候选次序。同一模型输入若因随机教师选了另一个动作，将不会被计为同一任务；重排候选也可能被漏计。后续应以**不含标签、候选按稳定语义对齐**的输入身份查交集，再单独分析标签冲突。

还需区分两个数字：

- 59.53%→58.39% 是混合 train/val/test 全量池的去重再加权变化，不能用作发布模型的泛化指标。
- 报告中 val 36.69%→35.42%、test 40.34%→37.39% 对应 seed 42 的 last 检查点读数；不能把相同降幅直接套到 best val=38.00% 或另外两个 seed。

必须在去污染的验证集上重评现有 best/last，后续训练用清理后的验证集选 checkpoint；最终确认使用未参与调参的新 roots。发现后如实披露重复，并不等于完成消除重复评估的验收。

### [P2] 训练“零准确率崩塌”已可从控制流定位

位置：`python/train_spatial_resnet.py` 的 `run_epoch` 总更新检查和外层 epoch 循环。

达到 global update limit 后，`run_epoch` 不再执行 batch，返回零样本统计；外层继续进入新的 epoch、验证并推进 scheduler，随后把连续零准确率判成训练退化。

三个 stageB 记录完全一致：第 2,000 epoch 已用完 16,000 更新；第 2,001～2,003 epoch 的 train loss/acc 全为 0，第 2,003 标 `train_accuracy_degradation`。这是预算耗尽后没有正常退出，不能称为数值崩塌，也不应再标“原因未知”。

修复应在到达总更新数后正常停止，明确 `stopReason=GLOBAL_UPDATE_LIMIT`，保存真正的 final/state/统计；零消费 epoch 不更新训练指标或 scheduler。当前 final 模型的可拟合结果仍可成立，但训练生命周期和恢复逻辑须单独回归。

## 5. 其他验收与身份问题

- G0 源码快照记录的是本轮修改前状态；当前训练器、parity 工具与快照的 SHA 不同。差异已部分说明，但应补运行时/final 快照和每次实验依赖摘要。
- `compare_source_snapshots.mjs` 把新快照覆盖进旧记录映射，又用 mtime 判断差异只是换行；mtime 不能证明内容相同，字节 SHA 不同也不能未经验证归因于换行。应保存原始内容/patch 或双方规范化摘要，无法证明则写 UNKNOWN。
- 原 task_status 已将 T14-07/08/09 标为 INCONCLUSIVE、T14-10 DEFERRED；“V14 已全部执行完毕”只能理解为本次运行结束，不能理解为原任务书验收全部完成。
- 真正的搜索教师回合改造、64/256/1024 预算对照和教师强度确认仍未执行。启发式探针不能代替这些任务。
- 正式数据集、模型训练和开发对战有实际产物，应保留。修正文档与状态，不能把本轮真实进展全部抹成失败。

## 6. 后续方向与建议顺序

我建议下一轮以“修正最少必要缺陷后，完成一个公平的泛化改善实验”为目标。不要再把全部资源用于 tiny-fit，也不要依据当前错误探针优先大改启发式策略。

| 顺序 | 工作 | 最小验收结果 |
|---|---|---|
| P0-A | 修教师探针的状态重放、固定 seed、联盟视角；区分种子多样性 | 同源 stateHash/合法集全匹配；固定输入重复可复现；跨 seed 差异独立报告 |
| P0-B | 修升级前后反击投影、历史 schema 分派、总更新停止 | 本文反例通过；原引擎规则保留；旧 schema 输入兼容或明确拒绝；预算退出不产生假崩塌 |
| P0-C | 清理跨分区相同输入，重评各 seed 的 best/last，冻结干净验证集 | 输入身份不含标签；跨分区污染为 0 或明确隔离；每个检查点有独立准确率和 hash |
| P1 | 重做等工作量 D0/D1/D2 | 三组额外更新一致（建议均 1,500）；D1/D2 唯一新状态数、分层和曝光匹配；标签查询不改变行为轨迹 |
| P1 | 在真实学生失败状态做有限反事实分析 | 选 20～50 个不同 root/阶段窗口，比较同状态下模型、教师与替代动作到玩家阶段边界及对手回应；记录预算与 UNKNOWN |
| P2 | 根据已证实错误增加独立轨迹与关键状态 | 按遗漏收益、兵力损失、招募经济、回合时序等错误分层；固定更新预算做数据收益实验 |

P1 对照建议从现有同一 C1 检查点开始，三组同时采用修正后的相同输入与标签版本。若输入 schema 改变，则先训练/冻结一个共同的新基线，禁止一组吃旧特征、一组吃新特征。正式三 seed 比较不沿用污染验证集挑 best。

对 `end_turn` 的操作条件：先证明某类机会窗口中结束确实更差，再补该类状态和正确标签；若主要问题是残血单位无有效行动，模型选择结束可能合理，不应处罚。

是否增加模型容量：目前没有优先依据。小样本已能拟合；正式数据存在泛化差距和实验污染。待干净验证集、受控纠错仍暴露特定不可表达的规则信息时，再做必要特征或架构消融；“所有目标原始输入 hash 不同”不等于实际网络的局部池化表示具有充分信息。

是否减小 weight decay/加长正式训练：tiny-fit 只说明这组记忆任务在增加预算后能解决，不能证明正式泛化收益。保留正则对照，在固定干净验证集上观察学习曲线与对战，不直接把 16,000 更新推广到所有正式运行。
