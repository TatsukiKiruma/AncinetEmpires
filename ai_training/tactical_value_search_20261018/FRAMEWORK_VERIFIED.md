# 事件守卫修订：保留原框架，补齐接管条件

原四臂200槽使用`model_battle_search_ai.ts`，全部保留。追加50槽使用独立的`model_battle_search_verified_ai.ts`、`search_verified.ts`和`battle_verified.ts`；Policy、Value、初态、座位、对手种子、分差系数与预算不变。两组均直接沿用公共BattleSearchAI的默认保底、候选缓存、自然胜直取、Takeover/Veto、友军连动和Maximin流程。原文件没有被修订版覆盖。

原通用接管只要求Value分差和关键损失约束，没有验证用户要求的实际事件。在ApkLike子面板观察到回退后，静态审查确认该条件过宽，追加以下开发修订；这不是独立泛化验证，也不把后验修订伪称原预注册参数。

|环节|修订行为|
|---|---|
|默认策略与候选|仍为同一分层网络，Top6；无HeuristicAI评分或回退|
|友军连动|仍为最多3个网络选择的非end动作；真实引擎逐步执行|
|事件统计|在敌方回应之前统计实际击杀、敌指挥官击杀、敌城堡夺取、占领、招募及无即时己方损血的正收益攻击|
|普通根动作接管|备选必须比默认连动实际多击杀敌指挥官或多夺取敌城堡，并满足原0.08分差与损失约束|
|默认end/wait纠正|还允许实际新增普通击杀、占领、招募或免费攻击；不能只靠分数更高接管|
|危险否决|仍要求合法集火致死威胁、关键单位真实损失或即时自然败局；不再单凭负Value否决|
|触发范围|优先指挥官或敌城堡等关键机会；最多6次权威移动后动作查询，不将触发探测当作网络连动计划|
|对手回应|仍含最多三个不同敌军的合法集火、movingThreat、策略回应及移动后攻击，取有界最坏叶子|
|预算|48显式树节点/步、2400/局；触发探测另记triggerProbes≤6，全部耗时仍受30秒/步、600秒/局、2000实际动作限制|

`verified_gate.ts`用实际引擎动作验证无事件普通移动不能接管、招募只纠正收尾、指挥官击杀与敌城堡夺取可作为接管资格，并核对重复决策、源状态不变和预算。`response_verified_regression.ts`继续验证移动后攻击、多军集火、冲突落点、零移动成本、纯网络友军连动与真实Maximin致死回应。`search-verified-purity-gate.json`记录41模块依赖图，无禁用启发式依赖。

`complete_verified.py`等待原200槽全部strict与归档前缀审计完成后才启动50槽，最大8并发。原200摘要保存为`battle-summary-original200.json`和`BATTLES_ORIGINAL200.md`；最终`battle-summary.json`与`BATTLES.md`合并250槽，完整列出初版与修订版，任何失败、截断或旧模型均不被替换。
