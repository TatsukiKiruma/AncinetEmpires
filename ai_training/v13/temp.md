## 二、为什么效果仍然差？最重要的是这几类问题

### 1. 训练时和实战时，模型面对的候选动作不是同一个集合

这是我认为应当最先处理的问题之一。

在 `tools/convert_archive_to_spatial.ts` 中，训练样本默认最多保留 **48 个候选动作**。超过上限时，先强制保留教师动作和指挥官招募动作，再从合法动作列表前部补足。

但在 `shared_spatial_policy.ts` 中，实战推理会对**全部合法动作**编码、打分并选择最高分动作，没有对应的 48 候选限制。

这意味着训练任务实际上更接近：

> 在一组经过裁剪、而且保证包含正确答案的候选里，选出教师动作。

实战任务却是：

> 在全部合法动作中，识别真正值得执行的动作。

由此产生的风险是：训练时没有充分参与竞争的动作，实战中可能获得不合理的高分；候选内准确率也不能直接代表全候选表现。

**建议优先统一候选契约。** 小规模实验先使用全合法候选；确实需要裁剪时，训练与推理共用一个不依赖正确标签的选择器，并报告教师动作在“强制插入之前”的真实覆盖率。

也要避免另一个误判：教师动作排在第 0 位，**不自动等于网络学会了位置作弊**。当前结构是逐候选共享打分，真正明确存在的问题是候选覆盖和竞争分布不同。

### 2. 数据不仅是“少”，还没有明确区分在模仿谁

48,714 行状态不是没有价值，但它们来自 **37 局轨迹**，不等于模型已经见过几万次独立的战略演化。长局还会贡献更多训练行，容易让某些地图、阶段和座位占据过高权重。

更关键的是，后续报告发现，数据混合了 heuristic 和 apk-like 两类行为。在“招募和攻击都合法”的条件下，报告中的招募选择分别为：

* heuristic：644 / 5,556；
* apk-like：0 / 6,815。

这不是简单的整体动作比例差异，而是同类决策机会下的行为差异。

然而，转换后的空间样本没有保留清晰的 `behaviorPolicyId`、`labelTeacherId`，训练读取器也没有建立按教师来源处理的契约。这样做硬标签模仿，模型学习的可能是混合行为，而不是一个明确、经过检验的强策略。

**正确处理不是把混合对局全部丢掉。** 可以按原始行的策略来源筛选，也可以在这些状态上重新调用指定教师标注。尤其在 DAgger 中，“谁走出了这个状态”和“谁给这个状态标注答案”本来就应该是两个独立字段。

### 3. 已完成的主要训练目标，仍是“复制动作”，不是“改进决策”

当前预算模型和修正池模型都是：

```text
loss_mode = ce
value_weight = 0
```

也就是说，这两组运行主要学习一个离线动作标签，并没有通过价值损失学习新的长期胜负预测。

此外，即使离线模仿不错，学生一旦选择了不同动作，后续遇到的局面也会变化。继续在固定教师轨迹上增加 epoch，不能替代对学生实际遇到的错误状态进行纠正。这也是 DAgger 这类方法要处理的核心问题。([Proceedings of Machine Learning Research][1])

因此，后续应该从：

> 固定归档 → 反复拟合教师单一动作

推进到：

> 明确教师 → 学生实战访问状态 → 教师纠错 → 等训练预算对照 → 独立对战验证。

但不要因此立即把未校准的价值头接进搜索。策略模仿、动作排序和价值学习应分别建立有效基线。

### 4. 当前搜索教师并不像名字暗示的那么完整

`BattleSearchAI` 的设计有继续发展的价值，但目前不能把它当作可靠的最优答案来源。

源码中，执行候选动作后，最多继续走 **3 个己方原子动作**。如果此时仍然轮到己方，就直接返回静态局面估值，**不一定走到对手回应阶段**。只有转到其他玩家时，才探测有限的对手动作，而且是攻击、占领优先的前几个候选。

这对回合制战棋非常重要：一个回合可能包含多个单位的移动、攻击、占领和部署。搜索三次原子动作，不等于搜索了一个完整回合。

还有一个一致性问题：实际策略复用有状态的随机流，标签工具则为每个候选创建新 AI，且种子按候选**序号**派生；运行策略与标签工具的候选预算也不同。因而：

**同样顺序重复运行可复现，不代表候选重排不变，也不代表标签工具准确复刻了实际教师。**

我的建议是先统一教师内核，明确回合边界和有效敌方回应，再验证标签质量。**“产生了 108 个不同数字”是进步，但不是“这些数字已经能教出强 AI”的证明。**

至于报告中的 BattleSearchAI **17/20**，后续审计已经说明没有原始对局制品，只有 console 陈述。因此值得重跑，但不能直接当作已核验的强度成绩。

### 5. 编码与网络结构可能限制上限，但现在不宜先换大模型

默认网络使用 24 通道、20×20 棋盘，32 个中间通道和两个残差块。按源码中的卷积层数计算，局部理论感受野是 **11×11**；策略头主要组合行动者、落点、目标点特征和全局标量。代码已经提供可选的全局 policy GAP，但默认关闭。

编码还把多个敌对玩家聚合起来，将单位压缩为较粗的兵种类别，威胁图采用移动距离加射程的简化曼哈顿覆盖，而非精确合法攻击范围。

这些可能影响多人局中的敌方轮次判断、远端协同和特殊战术。不过，**这还是需要通过特征碰撞与消融实验验证的假设，不是已经证明的唯一根因。**

优先顺序应是：先统一数据与推理，再测试已有 GAP 开关；发现确切的信息缺失后补编码，最后才考虑更深网络或更复杂结构。

## 三、这次还发现了几处需要立即修复的代码问题

这些问题与“路线是否正确”不同，属于可以明确修复和回归测试的工程缺陷。

| 问题                       | 源码表现                                                    | 影响                        |
| ------------------------ | ------------------------------------------------------- | ------------------------- |
| **训练 loss 重复累计**         | `run_epoch` 在训练更新块中累计一次，又在公共尾部累计一次。                     | 训练日志通常被放大；并不是梯度更新了两次。     |
| **价值预测与标签掩码不一致**         | 预测值按“非空且 mask=true”筛选，标签只按“非空”筛选。                       | 混合掩码批次可能错误广播或直接报错。        |
| **显式文件缺失后静默改变实验**        | 指定的 split manifest 不存在时回退；初始化 checkpoint 路径不存在时也可能从头训练。 | 实际运行不一定是报告所声称的切分或初始化。     |
| **初始化 seed 与切分 seed 耦合** | 同一个 seed 同时影响网络随机性与 episode 分区。                         | 三 seed 结果不是固定验证集上的纯初始化重复。 |
| **注入权重与遥测 SHA 脱节**       | 替换 predictor cache 后，SHA 仍来自静态 registry。                | 实际执行新权重，却可能记录旧模型身份。       |

对应问题可在训练器和适配器源码中直接确认。

我对价值掩码问题做了隔离复现：

```text
目标：       [+1, -1]
有效掩码：   [true, false]
预测：       [0.25, 0.75]

当前写法得到的 loss：1.0625
正确一致掩码的 loss：0.5625

第一个预测的梯度：
当前写法：+0.5
正确写法：-1.5
```

也就是说，某些形状下它不只是“多算一点误差”，而是可能**悄悄反转梯度方向**。另一些形状会直接报错。复现脚本和实际输出已经放入执行包。

不过，必须划清边界：**不能据此断言之前的模型就是被错误价值监督训坏的。** 已读取的训练运行是 `value_weight=0`，本轮也没有扫描真实数据以确认这些混合掩码案例实际出现过。它是必须修复的缺陷，不是已经证实的历史败因。

## 四、V12 报告中有几项结论需要纠正

### “P2 镜像 8/8，所以只有 P2 能赢”——证据没有这么强

配对结果只有两个 seed。代码在四个候选座位循环里，重复运行相同的全启发式镜像。因此，“镜像 8/8”实际上对应的是**两个独立配置各重复四次**，不是八次独立观察。

合理结论是：

> 在这两个 seed 下，全启发式镜像均由 P2 获胜；模型替换 P2 时，两局都输了。

这支持局部负面判断，但不支持“所有种子下只有 P2 能赢”，也不足以估计稳定的差距幅度。

### “同一 episode/player 的标签熵为 0，所以不能学价值”——这个推理不成立

后续报告据此认为价值信号不存在。

但如果一个玩家最终获胜，把 `+1` 分配给该玩家轨迹中的各个状态，同一局标签自然相同。这本身并不妨碍学习：价值模型需要利用**跨对局、跨状态**的差异泛化，而不是在同一局内部寻找不同的最终胜者。

真正应该担心的是独立对局不足、座位或策略身份捷径、标签缺失、行权重偏斜，以及没有独立校准，而不是把“终局回报沿轨迹广播”视为数学上不可学习。

### “扩到 48k 准确率没提高，所以扩数据无用”——不是有效的规模结论

预算模型和修正池模型的验证集分别是 3,000 行与 5,495 行，已经不是同一组固定验证样本；再加上 seed 与切分耦合，不能把准确率差值直接解释为数据规模的作用。

应固定验证集和训练预算，再比较新增独立轨迹的效果。

**所以，我不赞成直接照搬 V12 报告中所有“已证明无效”的判断。报告中的原始事实有价值，但部分因果解释明显超过了证据。**

## 五、我建议的后续路线

**保留空间网络方向，但调整执行顺序：**

> **修训练与身份契约 → 同协议测现有权重 → 明确教师的模仿基线 → 经验证的搜索蒸馏 → 学生状态上的 DAgger → 独立强度确认与部署。**

搜索负责寻找更好的选择，网络负责吸收并泛化这些选择，再辅助后续搜索，这与 Expert Iteration 的基本方向一致。但它在本项目里能否奏效，仍必须通过教师资格和等预算对照来验证。([arXiv][2])

我不建议现在立即从零启动庞大的 PPO/AlphaZero 式训练，也不建议先花大量时间转换全部归档。先用较小、可信、分布一致的数据完成一个真正可解释的改进实验。

任务书已经拆成以下阶段：

| 优先级      | 任务                                     | 必须交付的结果                                          |
| -------- | -------------------------------------- | ------------------------------------------------ |
| **P0**   | T13-00～04：冻结工件、修训练器、修评测、恢复教师来源、统一候选和编码 | 真实哈希、回归测试、固定切分、候选覆盖与 Python/TS 一致性结果             |
| **P1**   | T13-05：重测现有模型                          | 至少测当前前端实际权重、`budget_s42`、`v2_honest_s42`，不能只测旧模型 |
| **P1**   | T13-06～07：验证搜索教师并完成小规模训练               | 明确教师的真实 CE 基线必须完成；搜索教师合格后再训排序器                   |
| **P2**   | T13-08：DAgger 和等工作量消融                  | 证明纠错数据被实际优化，收益不是来自多训练或多搜索                        |
| **条件分支** | T13-09～10：价值头、冻结确认、浏览器验收               | 校准、独立对战、实际加载身份、延迟与回退全部通过后才提出部署                   |

第一轮训练可以从 **32～64 个独立训练 root、512～2,048 个重点决策点**做验证性实验。这是我建议的小规模实验量，**不是足以训出强 AI 的保证**。先观察是否能学会明确教师、是否能减少关键错误，以及收益是否进入真实对战，再决定扩大哪一种数据。

文档还明确要求：**这一轮不能再次只完成审计、最后写“建议下次训练”。** 通过前置检查后，至少完成一个明确教师的真实训练与对应评测；搜索教师不合格时，可以停止搜索蒸馏支路，但不能用它作为不做基础训练验证的理由。

## 最终评价

当前工作值得保留的部分很多：完整预算补训、数据身份修复、实际优化消费记录、配对评测方向，以及更丰富的搜索标签。它们都不是无效劳动。

但是，**当前还没有足够证据证明“修正后的最好模型”在统一协议下究竟有多强，也没有证明搜索标签已经能训练出更好的策略。**

最应该立即执行的两个动作是：

**一是把 `v2_honest_s42.json` 放进可信的配对评测，而不是继续用旧 `budget_s42` 代表全部新进展；二是修复“训练裁剪到 48 候选、实战使用全候选”的契约差异，再完成明确教师的小规模对照训练。**

这比继续堆 epoch、直接重放全部归档，或立刻换一个更大的网络，更能回答你真正关心的问题：**模型到底能不能学会更好的决策，以及下一笔训练资源应该花在哪里。**
