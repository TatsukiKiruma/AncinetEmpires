# Stage 7 后台执行入口

本次接手续跑保留了原 P1 进程和原 `game_worker.bundle.mjs`。原始交接、失败尝试和现场快照见 `BACKGROUND_HANDOFF.md`、`before/`、`attempt1/`、`attempt2/`、`attempt3/`。当前状态以 `RUN_STATUS.json`、`B_P1_LIVE.json`、`STAGE7_CONTROLLER.json` 及对应门禁文件为准，旧快照中的进程描述不是实时状态。

`run_stage7.py` 持有本任务控制器互斥锁和防休眠锁。它先核对 Phase A 公共冻结和 C1 权重，做 Stage 7 类型检查、构建与 CPU 合同探针；不重跑 Phase A。`phase_b_manager.py` 先等待在途 P1 收据和服务退出，只有控制进程确实消失且没有门禁收据才接续同一数据库。真实门禁失败保留现场并停止。

- Phase B：固定 12/18 局基准保留；统计完整搜索根与复核有效教师两个不同计数。物理 `meanWireMs` 排除预热，和含队列逻辑延迟分开。已选配置硬门不通过时不再运行后续配置。Stage 6 的真实工作负载不同；通过前置硬门才运行同初态、同配额的 G0/双异步单服务对照，单列与旧报告估计值的差异。
- Phase C：仅在 B 通过后加载冻结 Dev 面板，用 36 根评估 `W=1..8`，再运行 C1 的 Dev-18/54；全量复用快筛的逐局收据。Soft budget 截止、传输硬超时与时间判负分别保留。
- Phase D：每 20 局配额固定为人数 5/9/6、对手 10 HardAI / 7 C1 / 3 混编。轨迹从官方地图或上代联赛开局；开发与吞吐轨迹均不进入训练。每批 30 条按人数等权，18 条新样本、12 条来自已准入的 Stage 5/6 训练回放；只有候选完整教师的有效子集产生策略监督，只有自然局产生价值监督。C1 锚定在回放上计算。两轨模型各有检查点、离线开发、导出对拍和独立在线收据。
- Phase E：独立复核 54 份晋级收据后才原子创建一次性令牌。顺序是 C1 与候选的 Sealed-54、候选 Historical-40、重编码 Sealed-Offline-329；令牌创建前不打开封存面板或原始父局。结果不回流训练，不改应用默认模型。

代码级验证不能替代正式对局、训练或封存结果。最终证据会由实测收据生成，不调用旧的固定数字收官脚本。
